# 먼저 알아 둘 것 (Prerequisites)

먼저 알아 둘 것

📌 이 절에서 알게 될 것: 논문을 읽는 데 필요한 네 가지 생각, 함수·조건·재귀·기호와 목록.

함수: 넣으면 나오는 기계

해설·해석

함수는 무엇을 넣으면 정해진 것이 나오는 기계입니다.

자판기를 떠올려 보세요. 버튼 번호를 넣으면 음료가 나옵니다.

같은 번호를 넣으면 늘 같은 음료가 나옵니다. 이것이 함수의 핵심입니다.

조건: 만약 ~이면

해설·해석

조건은 상황에 따라 다른 답을 고르는 규칙입니다.

예: “비가 오면 우산, 아니면 모자.”

질문을 위에서부터 차례로 보고, 처음으로 “예”가 나온 줄의 답을 고릅니다.

질문(위에서부터)답
비가 오나?우산
햇빛이 강한가?모자
그 밖의 모든 경우아무것도 안 챙김

이 논문의 ‘조건식’이 바로 이런 모양입니다.

재귀: 자기 자신을 다시 쓰는 규칙

해설·해석

재귀는 문제를 더 작은 같은 문제로 바꾸어 푸는 방법입니다.

러시아 인형(마트료시카)을 생각해 보세요. “가장 작은 인형 찾기”는 이렇게 풀 수 있습니다.

  1. 인형을 연다.
  2. 안에 인형이 없으면, 지금 인형이 가장 작은 인형이다.
  3. 안에 인형이 있으면, 그 인형으로 1번부터 다시 한다.

규칙 안에 “다시 한다”가 들어 있지요. 그래도 인형은 점점 작아지니 언젠가 끝납니다.

기호와 목록

해설·해석

기호는 숫자가 아닌 이름표입니다. 예: APPLE, RED.

목록은 기호를 차례로 늘어놓은 것입니다. 예: 장보기 목록 (APPLE, MILK, EGG).

목록 안에 또 목록이 들어갈 수도 있습니다. 예: (APPLE, (MILK, EGG)).

이 논문은 숫자가 아니라 이런 기호와 목록을 계산하는 방법을 다룹니다.

# 전반적인 해설 (Overview)

전반적인 해설

📌 이 절에서 알게 될 것: 이 논문이 무엇을 말하는지, 왜 중요한지, 그 뒤에 무엇이 일어났는지.

한 줄 요약

해설·해석

기호와 목록을 다루는 계산은 아주 적은 재료만으로 모두 쓸 수 있다.

그리고 그 계산 규칙 자체도 같은 기호와 목록으로 적을 수 있다.

재료는 몇 개뿐

해설·해석

매카시가 쓴 재료는 다음과 같습니다.

  • 목록의 맨 앞을 꺼내는 일
  • 맨 앞을 뺀 나머지를 꺼내는 일
  • 두 개를 붙여 새 묶음을 만드는 일
  • 이것이 낱개 기호인지 묻는 일
  • 두 기호가 같은지 묻는 일

여기에 “만약 ~이면” 규칙과 “같은 규칙을 다시 쓰기”(재귀)를 더합니다.

논문은 이것만으로 컴퓨터가 계산할 수 있는 것은 모두 만들 수 있다고 말합니다.

논문 원문
“We get a much larger class of functions (in fact, all computable functions) when we allow ourselves to form new functions of S-expressions by conditional expressions and recursive definition.”

🎁 예시로 따라가 보기: 상자 속 첫 물건 찾기

해설용 예시입니다. 다만 같은 계산이 논문에 ff라는 함수로 나옵니다(3절).

왜 중요한가

해설·해석

첫째, 숫자가 아닌 기호를 계산하는 방법을 깔끔하게 정리했습니다.

둘째, 프로그램을 데이터와 같은 모양으로 적었습니다. 그래서 프로그램이 다른 프로그램을 읽고 실행할 수 있습니다.

셋째, 그런 실행기, 즉 만능 함수를 몇 줄로 적어 보였습니다.

넷째, 다 쓴 메모리를 컴퓨터가 스스로 치우는 방법을 설명했습니다.

그 뒤에 일어난 일

해설·해석

논문에 적힌 언어가 LISP입니다. ‘목록 처리기(LISt Processor)’라는 뜻입니다.

매카시의 회고에 따르면, 함께 일하던 스티브 러셀이 논문의 ‘만능 함수’를 직접 기계어로 옮겨 실제로 돌아가는 실행기를 만들었습니다.

‘알아서 메모리 치우기’는 오늘날 가비지 컬렉션(쓰레기 수거)이라 불리며 많은 언어가 씁니다.

제목의 “Part I”에 이어질 Part II는 끝내 쓰이지 않았다고 매카시가 회고했습니다.

출처: McCarthy, “History of LISP” (ACM SIGPLAN Notices 13(8), 1978) PDF
더 알고 싶다면: 논문의 흐름 한눈에 보기
해설·해석 논문은 다음 순서로 나아갑니다.
  1. 함수를 정의하는 도구를 준비한다: 조건식, 재귀 정의, 이름 없는 함수 표기(λ), 이름 붙이기(label).
  2. 계산 대상인 ‘S-식’(기호 묶음)을 정의한다.
  3. 기본 연산 다섯 개로 여러 함수를 만든다.

  5. S-식으로 적힌 함수를 실행하는 만능 함수 apply/eval을 정의한다.
  6. IBM 704 컴퓨터의 메모리에 S-식을 담는 방법과 메모리 회수 방법을 설명한다.
  7. 비슷한 다른 방식(linear LISP)과, 순서도를 재귀 함수로 바꾸는 방법을 보인다.

# 1. 논문이 나온 맥락

1. 논문이 나온 맥락

📌 이 절에서 알게 될 것: LISP가 어떤 목적으로, 어떤 컴퓨터에서 만들어졌는지.
논문 원문 논문 첫 문장입니다.
“A programming system called LISP (for LISt Processor) has been developed for the IBM 704 computer by the Artificial Intelligence group at M.I.T.”

논문은 LISP의 목적을 다음과 같이 밝힙니다.

  • ‘Advice Taker’라는 시스템을 실험하기 위해 만들었다.
  • Advice Taker는 명령문뿐 아니라 서술문도 다루고 “common sense”를 보이도록 구상된 시스템이다.
  • Advice Taker 제안은 1958년 11월에 처음 나왔다.

또 LISP가 여러 단계의 단순화를 거쳐, 어떤 기호식들의 부분 재귀 함수를 나타내는 체계가 되었다고 말합니다. 이 체계는 IBM 704나 다른 어떤 컴퓨터와도 무관하다고 덧붙입니다.

해설·해석

당시 대부분의 프로그램은 숫자 계산이 목적이었습니다.

매카시는 인공지능 연구를 위해 문장과 논리식 같은 기호를 다루는 도구가 필요했습니다.

매카시의 회고에 따르면 LISP 개발은 1958년에 시작됐습니다. 또 car, cdr 같은 이름은 IBM 704의 기계어 단어 구조(‘address’ 부분, ‘decrement’ 부분)에서 왔습니다.

# 2. 함수와 함수 정의

2. 함수와 함수 정의

📌 이 절에서 알게 될 것: 매카시가 새로 내놓은 ‘조건식’과, 그것으로 재귀 함수를 정의하는 방법.

2-1. 부분 함수와 참·거짓

논문 원문
  • 부분 함수(partial function): 정의역의 일부에서만 정의된 함수. 계산이 끝나지 않는 경우가 있으니 자연히 생긴다.
  • 명제식(propositional expression): 값이 T(참) 또는 F(거짓)인 식. 예: x < y, x is prime.
  • 술어(predicate): 값이 T와 F뿐인 함수.

2-2. 조건식

논문 원문 논문은 조건식이라는 개념이 새롭다고 봅니다(“believed to be new”). 모양은 다음과 같습니다.
(p1 → e1, ⋯, pn → en)

읽는 법은 “p1이면 e1, 아니고 p2이면 e2, ⋯”입니다. 값을 정하는 규칙은 다음과 같습니다.

  1. p들을 왼쪽부터 살핀다.
  2. 값이 정의되지 않은 p보다 먼저 T인 p를 만나면, 그에 대응하는 e의 값이 답이다(그 e가 정의된 경우).
  3. T인 p보다 정의되지 않은 p를 먼저 만나면, 답은 정의되지 않는다.
  4. 모든 p가 거짓이면, 답은 정의되지 않는다.
  5. 첫 번째로 참인 p에 대응하는 e가 정의되지 않으면, 답은 정의되지 않는다.

논문의 예:

(1 < 2 → 4, 1 > 2 → 3) = 4(2 < 1 → 4, T → 3) = 3
(2 < 1 → 0/0, T → 3) = 3(2 < 1 → 3, T → 0/0)은 정의되지 않음
|x| = (x < 0 → −x, T → x)sgn(x) = (x < 0 → −1, x = 0 → 0, T → 1)

각주 2에서 매카시는 조건식을 Algol 60에 넣자고 제안했으나 이 표기는 받아들여지지 않았고, Algol 60이 채택한 if … then … else는 John Backus가 제안했다고 적습니다.

해설·해석

0/0처럼 뜻이 없는 식이 있어도, 그 줄에 도달하지 않으면 괜찮다는 점이 중요합니다.

이 성질 덕분에 다음 절의 재귀 정의가 무한히 돌지 않고 멈출 수 있습니다.

2-3. 재귀 함수 정의

논문 원문 조건식을 쓰면 정의하려는 함수가 식 안에 다시 나와도 순환에 빠지지 않습니다.
n! = (n = 0 → 1, T → n · (n − 1)!)

논문의 다른 예:

  • 최대공약수: gcd(m, n) = (m > n → gcd(n, m), rem(n, m) = 0 → m, T → gcd(rem(n, m), m))
  • 뉴턴법 제곱근: sqrt(a, x, ε) = (|x² − a| < ε → x, T → sqrt(a, ½(x + a/x), ε))

논리 연결사도 조건식으로 정의합니다. 예: p ∧ q = (p → q, T → F), p ∨ q = (p → T, T → q), ¬p = (p → F, T → T). 그래서 p가 거짓이고 q가 정의되지 않으면 p ∧ q는 거짓이지만 q ∧ p는 정의되지 않습니다. 논문은 이 비가환성이 바람직하다고 말합니다.

2-4. 함수와 형식, λ 표기, label

해설·해석

“y² + x”는 그 자체로는 함수가 아닙니다. 3과 4를 어느 변수에 넣을지 모르기 때문입니다.

그래서 “변수 순서는 (x, y)”라고 정해 주는 표기가 필요합니다. 이것이 λ 표기입니다.

그런데 λ만으로는 자기 자신을 부르는 함수에 이름을 붙일 수 없습니다. 그래서 label을 씁니다.

더 알고 싶다면: λ와 label의 정확한 정의
논문 원문

처치(Church)를 따라, y² + x 같은 식을 형식(form)이라 부릅니다. y² + x(3, 4)는 값이 13인지 19인지 불분명합니다.

E가 변수 x1, ⋯, xn의 형식이면, λ((x1, ⋯, xn), E)는 인자를 그 순서대로 E의 변수에 대입해 계산하는 n변수 함수입니다. 예: λ((x, y), y² + x)(3, 4) = 19.

λ의 변수 목록에 있는 변수는 묶인(bound) 변수라 이름을 바꿔도 뜻이 같습니다. 묶이지 않은 변수는 자유(free) 변수입니다.

label(a, E)는 식 E를 나타내되, E 안의 a는 식 전체를 가리킨다고 해석합니다. 예: label(sqrt, λ((a, x, ε), (|x² − a| < ε → x, T → sqrt(a, ½(x + a/x), ε)))).

감사의 말에 따르면, λ 표기가 재귀 함수 이름 붙이기에 부족하다는 점은 N. Rochester가 알아챘고, 그는 label과는 다른 해법도 찾았습니다.

# 3. 기호식(S-식)과 그 함수들

3. 기호식(S-식)과 그 함수들

📌 이 절에서 알게 될 것: 계산 대상인 S-식, 기본 연산 다섯 개, 그리고 프로그램을 실행하는 만능 함수. 이 글의 중심입니다.

3-1. S-식이란

논문 원문 S는 symbolic(기호)의 약자입니다. 정의는 두 줄입니다.
  1. 원자 기호(atomic symbol)는 S-식이다.
  2. e1, e2가 S-식이면 (e1 · e2)도 S-식이다.

원자 기호로는 대문자 라틴 문자와 숫자로 된 문자열을 씁니다. 예: A, ABA, APPLE PIE NUMBER 3. 한 글자가 아닌 이름을 쓰는 이유로 논문은 두 가지를 듭니다.

  • 프로그램에는 수백 개의 기호가 필요한데, IBM 704가 인쇄할 수 있는 문자는 47개뿐이다.
  • 영어 단어를 기호로 쓰면 기억하기 쉽다.

목록 (m1, m2, ⋯, mn)은 (m1 · (m2 · (⋯ (mn · NIL) ⋯)))의 줄임말입니다. NIL은 목록 끝을 나타내는 원자 기호입니다. 줄임 규칙은 다음 셋입니다.

  1. (m)은 (m · NIL)
  2. (m1, ⋯, mn)은 (m1 · (⋯ (mn · NIL) ⋯))
  3. (m1, ⋯, mn · x)은 (m1 · (⋯ (mn · x) ⋯))

1995년 메모(각주 3): 당시에는 목록 원소를 쉼표로 구분했으므로 기호 안에 빈칸을 허용할 수 있었다.

해설·해석

S-식은 결국 둘씩 묶은 쌍입니다. 쌍 안에 또 쌍이 들어갈 수 있습니다.

목록은 “첫 원소”와 “나머지 목록”의 쌍을 계속 이어 붙인 것입니다.

3-2. 기본 함수 다섯 개

논문 원문 함수를 적을 때는 S-식과 구별하려고 소문자 이름, 대괄호, 세미콜론을 씁니다(예: car[cons[(A · B); x]]). 논문은 이런 표기를 M-식(meta-expression)이라 부릅니다.
함수뜻논문의 예
atom[x]x가 원자 기호면 T, 아니면 Fatom[X] = T, atom[(X · A)] = F
eq[x; y]x, y가 둘 다 원자일 때만 정의. 같은 기호면 Teq[X; X] = T, eq[X; (X · A)]는 정의되지 않음
car[x]x가 원자가 아닐 때만 정의. car[(e1 · e2)] = e1car[((X · A) · Y)] = (X · A)
cdr[x]x가 원자가 아닐 때만 정의. cdr[(e1 · e2)] = e2cdr[((X · A) · Y)] = Y
cons[x; y]언제나 정의. cons[e1; e2] = (e1 · e2)cons[(X · A); Y] = ((X · A) · Y)

세 함수는 다음 관계를 만족합니다.

  • car[cons[x; y]] = x
  • cdr[cons[x; y]] = y
  • cons[car[x]; cdr[x]] = x (x가 원자가 아닐 때)
해설·해석
  • car: 쌍의 왼쪽(목록이라면 첫 원소)
  • cdr: 쌍의 오른쪽(목록이라면 첫 원소를 뺀 나머지)
  • cons: 두 개를 묶어 새 쌍 만들기

3-3. 재귀로 만든 S-함수

논문 원문
  • ff[x]: 괄호를 무시했을 때 x의 첫 원자 기호. ff[x] = [atom[x] → x; T → ff[car[x]]], 예: ff[((A · B) · C)] = A
  • subst[x; y; z]: z 안의 원자 y를 모두 x로 바꾼 결과. subst[x; y; z] = [atom[z] → [eq[z; y] → x; T → z]; T → cons[subst[x; y; car[z]]; subst[x; y; cdr[z]]]], 예: subst[(X · A); B; ((A · B) · C)] = ((A · (X · A)) · C)
  • equal[x; y]: 같은 S-식이면 T
  • null[x] = atom[x] ∧ eq[x; NIL]

목록용 함수로는 다음이 정의됩니다.

  • append: 두 목록 잇기. 예: append[(A, B); (C, D, E)] = (A, B, C, D, E)
  • among: x가 목록 y의 원소인가
  • pair: 두 목록의 짝 목록. 예: pair[(A, B, C); (X, (Y, Z), U)] = ((A, X), (B, (Y, Z)), (C, U))
  • assoc: 짝 목록에서 x의 짝 찾기. 예: assoc[X; ((W, (A, B)), (X, (C, D)), (Y, (E, F)))] = (C, D)
  • sublis: 짝 목록대로 한꺼번에 바꾸기

줄임말로 cadr[x]는 car[cdr[x]], caddr[x]는 car[cdr[cdr[x]]]입니다.

3-4. 프로그램을 데이터로: M-식을 S-식으로

해설·해석

지금까지 함수는 M-식(소문자, 대괄호)으로 적었습니다.

매카시는 이 함수들을 S-식으로도 적는 규칙을 정했습니다.

그러면 함수 자체가 데이터가 됩니다. 함수를 계산하는 함수를 만들 수 있게 됩니다.

더 알고 싶다면: 번역 규칙 여섯 가지
논문 원문 M-식 E의 번역을 E*라 씁니다.
  1. E가 S-식이면 E*는 (QUOTE, E).
  2. 소문자 변수·함수 이름은 대문자로. 예: car*는 CAR.
  3. f[e1; ⋯; en]는 (f*, e1*, ⋯, en*). 예: cons[car[x]; cdr[x]]*는 (CONS, (CAR, X), (CDR, X)).
  4. [p1 → e1; ⋯; pn → en]*는 (COND, (p1*, e1*), ⋯, (pn*, en*)).
  5. λ[[x1; ⋯; xn]; E]*는 (LAMBDA, (x1*, ⋯, xn*), E*).
  6. label[a; E]*는 (LABEL, a*, E*).

논문은 이 표기가 “writable and somewhat readable”하다고 평합니다.

3-5. 만능 함수 apply와 eval

해설·해석

apply는 “함수의 설명서(S-식)”와 “재료(인자)”를 받아 결과를 내는 함수입니다.

논문은 이것이 이론에서는 만능 튜링 기계의 역할을, 실제로는 인터프리터(프로그램 실행기)의 역할을 한다고 말합니다.

실제 일은 eval이 합니다. eval은 식 하나와 “이름–값 짝 목록”(a)을 받아 식의 값을 냅니다.

논문 원문 논문의 예:
λ[[x; y]; cons[car[x]; y]][(A, B); (C, D)] = apply[(LAMBDA, (X, Y), (CONS, (CAR, X), Y)); ((A, B), (C, D))] = (A, C, D)

apply[f; args] = eval[cons[f; appq[args]]; NIL]. 여기서 appq는 각 인자에 QUOTE를 씌워 “그 자체를 뜻한다”고 표시합니다.

더 알고 싶다면: eval의 전체 정의와 경우 나누기
논문 원문 
eval[e; a] = [
  atom[e] → assoc[e; a];
  atom[car[e]] → [
    eq[car[e]; QUOTE] → cadr[e];
    eq[car[e]; ATOM]  → atom[eval[cadr[e]; a]];
    eq[car[e]; EQ]    → [eval[cadr[e]; a] = eval[caddr[e]; a]];
    eq[car[e]; COND]  → evcon[cdr[e]; a];
    eq[car[e]; CAR]   → car[eval[cadr[e]; a]];
    eq[car[e]; CDR]   → cdr[eval[cadr[e]; a]];
    eq[car[e]; CONS]  → cons[eval[cadr[e]; a]; eval[caddr[e]; a]];
    T → eval[cons[assoc[car[e]; a]; evlis[cdr[e]; a]]; a]];
  eq[caar[e]; LABEL]  → eval[cons[caddar[e]; cdr[e]]; cons[list[cadar[e]; car[e]]; a]];
  eq[caar[e]; LAMBDA] → eval[caddar[e]; append[pair[cadar[e]; evlis[cdr[e]; a]]; a]]]


evcon[c; a] = [eval[caar[c]; a] → eval[cadar[c]; a]; T → evcon[cdr[c]; a]]
evlis[m; a] = [null[m] → NIL; T → cons[eval[car[m]; a]; evlis[cdr[m]; a]]]

논문의 설명을 정리하면 다음과 같습니다.

  1. e가 원자면, a에서 e와 짝지어진 것을 찾는다.
  2. e의 car가 원자면, QUOTE·ATOM·EQ·COND·CAR·CDR·CONS 중 무엇인지에 따라 처리한다. 그 밖의 원자 f면 a에서 f의 짝으로 바꿔 다시 계산한다.
  3. ((LABEL, f, E), e1, ⋯)는 짝 (f, (LABEL, f, E))를 a 앞에 붙이고 (E, e1, ⋯)를 계산한다.
  4. ((LAMBDA, (x1, ⋯), E), e1, ⋯)는 짝 ((x1, e1), ⋯)를 a 앞에 붙이고 E를 계산한다.

짝 목록 a를 쓰는 이유는 묶인 변수의 충돌(collision of bound variables)을 피하기 위해서라고 논문은 설명합니다.

1995년 메모(각주 5): “This version isn't quite right.” 실제로 구현된 판과의 비교는 Herbert Stoyan의 글을 보라고 적혀 있습니다.

# 4. 기계 속의 LISP (IBM 704)

4. 기계 속의 LISP (IBM 704)

📌 이 절에서 알게 될 것: S-식이 메모리에 어떻게 담기는지, 그리고 다 쓴 메모리를 어떻게 되찾는지.
논문 원문 논문은 LISP 시스템이 쓰였거나 쓰일 목적을 다음처럼 꼽습니다.
  1. LISP 프로그램을 기계어로 옮기는 컴파일러 작성
  2. 어떤 형식 논리 체계의 증명을 검사하는 프로그램
  3. 형식적 미분·적분 프로그램
  4. 술어 논리의 증명 생성 알고리즘 구현
  5. 결과가 숫자가 아닌 공식인 공학 계산
  6. Advice Taker 프로그래밍

4-1. 칸과 화살표: 리스트 구조

논문 원문

기계의 한 ‘단어(word)’를 두 칸짜리 상자로 그립니다. 왼쪽 칸은 address 부분, 오른쪽 칸은 decrement 부분입니다.

원자가 아닌 S-식 x는 단어 하나로 나타냅니다. address 부분에는 car[x]의 위치가, decrement 부분에는 cdr[x]의 위치가 들어갑니다.

같은 부분 구조를 여러 곳에서 함께 가리키는 것은 허용됩니다. 하지만 순환(자기 자신을 가리키는 고리)은 허용하지 않습니다.

리스트 구조의 장점으로 논문은 세 가지를 듭니다.

  1. 다룰 식의 크기와 개수를 미리 알 수 없어도 된다.
  2. 필요 없어진 칸을 하나씩 ‘빈칸 목록’에 돌려줄 수 있다.
  3. 여러 식에 들어 있는 같은 부분식을 한 번만 저장할 수 있다.

이름의 유래도 이 절에 나옵니다.

  • “car” is a mnemonic for “contents of the address part of register.”
  • “cdr” stands for “contents of the decrement part of register.”
  • “cons” is an abbreviation for “construct.”
해설·해석 실습 ①의 그림이 바로 이 방식입니다. 왼쪽 칸에서 아래로 가는 화살표가 car, 오른쪽 칸에서 옆으로 가는 화살표가 cdr입니다.

4-2. 기호의 정보 목록

논문 원문 원자 기호는 컴퓨터 안에서 ‘association list’라는 특수한 리스트 구조로 나타냅니다. 여기에는 인쇄용 이름(print name), 숫자 값, 기계어 루틴 위치 같은 정보를 담을 수 있습니다. IBM 704는 36비트 단어를 쓰고, 인쇄 가능한 문자는 6비트씩이라 한 단어에 여섯 글자가 들어갑니다. 1995년 메모(각주 6): 이것은 나중에 property list라고 불렸다.

4-3. 빈칸 목록과 자동 회수

해설·해석

새 쌍을 만들 때마다 메모리 칸이 하나씩 필요합니다.

쓰지 않는 칸은 ‘빈칸 목록’에 모아 둡니다.

빈칸이 다 떨어지면, 프로그램이 더는 닿을 수 없는 칸을 찾아 빈칸 목록으로 되돌립니다.

프로그래머가 직접 지울 필요가 없다는 점이 핵심입니다.

더 알고 싶다면: 회수 과정의 실제 설명
논문 원문

리스트 구조용 메모리 중 쓰이지 않는 레지스터(처음에는 약 15,000개)는 free-storage list라는 하나의 목록으로 묶입니다. 레지스터 FREE가 그 첫 위치를 가리킵니다.

회수는 다음 순서로 자동으로 일어납니다.

  1. 빈 레지스터가 필요한데 목록이 비었을 때에만 회수(reclamation) 주기가 시작된다.
  2. 기준 레지스터들에서 car–cdr 사슬로 닿는 모든 레지스터의 부호를 음수로 바꾼다. 이미 음수면 이미 방문한 것으로 본다.
  3. 리스트 구조 영역 전체를 훑어, 부호가 바뀌지 않은 레지스터를 free-storage list에 돌려준다.
  4. 닿을 수 있는 레지스터의 부호를 다시 양수로 돌린다.

논문은 회수에 몇 초가 걸리므로, 닿을 수 있는 목록이 메모리를 거의 채우지 않아야 효율적이라고 말합니다.

각주 7(나중에 덧붙인 저자 메모): “We already called this process “garbage collection”, but I guess I chickened out of using it in the paper—or else the Research Laboratory of Electronics grammar ladies wouldn't let me.”

해설·해석 오늘날 말로는 표시 후 쓸기(mark-and-sweep) 방식의 가비지 컬렉션입니다. 각주에 따르면 ‘garbage collection’이라는 말은 당시 이미 쓰였지만 논문 본문에는 넣지 않았습니다. 다만 이 각주가 1960년 원래 지면에는 없는 나중 메모라는 점에 주의하세요. 위키백과는 가비지 컬렉션 루틴을 MIT 대학원생 Daniel Edwards가 1962년 이전에 개발했다고 적고 있습니다(LISP 1.5 Programmer's Manual 인용). 이 학습서에서 그 매뉴얼을 직접 대조하지는 않았습니다(확인되지 않음).
출처: Wikipedia, “Lisp (programming language)”

4-4. 재귀 함수의 실행과 시스템 현황

논문 원문

재귀 함수의 루틴은 자기 자신을 서브루틴으로 부릅니다. 이때 임시 레지스터 값이 겹치지 않도록 SAVE와 UNSAVE 루틴이 ‘public push-down list’를 씁니다. 1995년 메모(각주 8): 지금은 stack이라고 부른다.

1960년 2월 현황으로 논문은 다음을 적습니다.

  • apply의 변형을 IBM 704용 프로그램 APPLY로 옮겼고, 이것이 LISP의 인터프리터 역할을 한다.
  • 함수를 원하는 만큼 S-식으로 정의할 수 있다.
  • S-식을 읽고 인쇄할 수 있다(직접 또는 자기 테이프).
  • 오류 진단과 선택적 추적 기능이 있다.
  • 컴파일된 함수는 해석할 때보다 약 60배 빠르다.
  • ALGOL 방식의 대입문과 go to를 쓰는 “program feature”가 있다.
  • 부동소수점 계산은 되지만 비효율적이다.
  • 프로그래머 매뉴얼을 준비 중이고, IBM 709용 판도 준비 중이다.
해설·해석 매카시는 회고에서 S. R. 러셀이 eval이 LISP 인터프리터 역할을 할 수 있음을 알아채고 곧바로 손으로 코딩했다고 적었습니다(“S.R. Russell noticed that eval could serve as an interpreter for LISP, promptly hand coded it”). 논문이 말하는 APPLY 프로그램과 이 일이 같은 것인지는 이 학습서에서 확인되지 않음입니다.

# 5. 다른 형식(linear LISP)과 순서도

5. 다른 형식(linear LISP)과 순서도

📌 이 절에서 알게 될 것: 문자열만 쓰는 변형 LISP, 그리고 순서도 프로그램을 재귀 함수로 바꾸는 방법.
논문 원문 linear LISP은 문자열(L-식)을 다룹니다. 함수 세 개와 술어 세 개를 씁니다.
  • first[x]: 첫 문자. 예: first[ABC] = A
  • rest[x]: 첫 문자를 뺀 나머지. 예: rest[ABC] = BC
  • combine[x; y]: 문자 x를 y 앞에 붙이기. 예: combine[A; BC] = ABC
  • 술어: char[x](한 문자인가), null[x](빈 문자열인가), x = y(같은 문자인가)

장점은 괄호·점·쉼표 같은 특별한 문자가 없다는 것입니다. 단점은 부분식을 꺼내기가 기본 연산이 아니라 꽤 복잡한 연산이라는 것입니다. 수학적으로는 linear LISP이 LISP을 포함하지만, 컴퓨터 루틴으로는 LISP이 본질적으로 더 빠르다고 논문은 말합니다.

해설·해석

마지막 절은 방향을 거꾸로 해 봅니다.

보통 프로그램(순서도)도 재귀 함수로 적을 수 있다는 것입니다.

순서도의 갈림길마다 “여기서부터 끝까지 일어나는 변화”를 함수 하나로 두면 됩니다.

더 알고 싶다면: 순서도 → 재귀 함수 공식
논문 원문

기계의 상태를 변수들을 모은 벡터 ξ로 둡니다. 입구 하나·출구 하나인 프로그램 블록은 ξ′ = f(ξ) 꼴의 함수로 정해집니다.

일반적으로, β가 n갈래 분기점이고 f1, ⋯, fn이 분기점 β1, ⋯, βn으로 이어지는 계산이라고 합시다. φ가 β에서 출구까지의 변환, φi가 βi에서 출구까지의 변환이면 다음과 같습니다.

φ[ξ] = [p1[ξ] → φ1[f1[ξ]]; ⋯; pn[ξ] → φn[fn[ξ]]]

위 공식의 마지막 항은 PDF에 φn[ξ]로 인쇄되어 있습니다. 앞 항들과의 일관성으로 보아 φn[fn[ξ]]로 읽었는데, 이것은 이 학습서의 해석입니다(1960년 지면과는 확인되지 않음).

# 6. 흔한 오해와 오늘날의 의미

6. 흔한 오해와 오늘날의 의미

📌 이 절에서 알게 될 것: 이 논문에 대해 잘못 알려지기 쉬운 점과 남긴 영향.
오해 1: “LISP 프로그램은 처음부터 괄호투성이 S-식으로 쓰도록 설계됐다.”
논문 원문 논문에서 함수는 M-식(car[x]처럼 대괄호와 세미콜론)으로 적고, S-식은 데이터와 ‘함수의 번역’에 씁니다.
해설·해석 위키백과에 따르면 M-식은 널리 쓰이지 않았고, 오늘날 LISP 계열 언어는 거의 모두 S-식으로 코드와 데이터를 함께 다룹니다.
출처: Wikipedia, “Lisp (programming language)”
오해 2: “논문의 eval은 그대로 완벽하게 돌아간다.”
논문 원문 1995년 메모가 “This version isn't quite right.”라고 밝힙니다. 실습 ③에서 인쇄된 정의를 그대로 돌려 보면 예 2가 멈추는 것을 볼 수 있습니다.
오해 3: “이 논문에는 Part II가 있다.”
해설·해석 매카시는 “Part II was never written but was intended to contain applications to computing with algebraic expressions.”라고 회고했습니다.
출처: McCarthy, “History of LISP” (1978) PDF
오해 4: “논문 본문에 ‘garbage collection’이라는 말이 나온다.”
논문 원문 본문은 ‘reclamation’이라고 씁니다. ‘garbage collection’은 나중에 덧붙인 각주 7에만 나옵니다.
해설·해석 오늘날의 의미: 이 논문의 생각들은 다음과 이어져 있습니다.
  • 조건식: 오늘날 거의 모든 언어의 if 식·삼항 연산자
  • 재귀와 고차 함수(maplist 같은 함수를 받는 함수): 함수형 프로그래밍의 기본기
  • 코드를 데이터로 다루기: 매크로, 인터프리터, 컴파일러를 같은 언어로 쓰는 전통
  • 자동 메모리 회수: 오늘날 많은 언어의 가비지 컬렉터
