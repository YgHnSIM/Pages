# 상자, 페이지, 점프, 메모지

### 포인터가 없던 세계에서 자기수정 코드가 필요했던 이유

어셈블리 포함 · 기초부터 해설하는 강의록

---

## 이 노트를 읽는 법

이 문서는 다음을 한 그림으로 연결한다.

- 메모리(상자)와 주소(호수)
- 명령 실행 순서(페이지 번호, PC)
- 점프와 `goto`
- 루프
- 자기수정 코드
- 포인터와 레지스터

대상은 **어셈블리를 한 줄도 모른다고 가정한 독자**다.  
본문에 나오는 기계어·어셈블리는 모두 바로 아래에서 단어 단위로 푼다.

권장 순서: 1장부터 차례로. 8장의 슬로모션 표는 그 앞을 읽은 뒤에야 의미가 있다.

## 0. 이 강의가 메우는 빈칸

| 층 | 빈칸 | 메운 뒤 보이는 것 |
|---|---|---|
| 기억 | 주소와 내용의 차이 | “1000을 더하라”와 “1000호를 더하라” |
| 실행 | 주소 번호가 곧 실행 순서? | PC라는 한 칸이 순서를 정한다 |
| 기호 | 어셈블리 한 줄이 무엇인가 | 상자 작업의 짧은 메모 |
| 제어 | 루프가 원시 기능인가 | 루프 = 뒤로 점프 + 상태 변화 |
| 언어 | `goto`는 별종인가 | 포장하지 않은 점프 |
| 반복 | 점프만 있으면 일이 되나 | 착지는 같아도 세계 상태는 달라야 한다 |
| 자기수정 | “코드를 고친다”의 구체성 | 요리책 빈칸을 메모지 대신 쓴다 |
| 포인터 | 포인터 = 특수 레지스터? | 포인터는 규칙, 레지스터는 손 |

# 1장. 창고: 번호와 내용

컴퓨터의 주기억장치(RAM)를 거대한 창고로 본다.

- 상자마다 **주소**라는 번호가 있다. `0`, `1`, `20`, `0x1000` …
- 각 상자 안에는 **숫자 하나**(또는 몇 바이트)가 들어 있다.
- CPU(일꾼)는 “몇 호를 열어라”, “그 숫자를 더하라” 같은 지시를 받는다.

예시:

| 주소(호수) | 상자 안 내용 |
|-----------|-------------|
| 20 | 7 |
| 21 | 3 |
| 22 | 10 |

합계를 구하면 \(7 + 3 + 10 = 20\) 이다.

구분:

- **주소** = 상자의 위치
- **내용** = 상자 안에 들어 있는 값

“20을 더하라”와 “20호 상자 안을 더하라”는 다른 말이다.  
이후 모든 오해는 이 한 줄이 흔들릴 때 생긴다.

---

# 2장. 레시피도 같은 창고에 있다

요리사는 레시피를 보고 요리한다. 컴퓨터의 레시피가 **프로그램**이다.

초창기 저장 프로그램 컴퓨터(폰 노이만 구조)는 레시피와 재료를 **같은 창고**에 넣는다.

```text
낮은 번호 쪽  = 레시피(명령)
높은 번호 쪽  = 재료(데이터)
```

약속일 뿐, 물리적으로는 둘 다 “상자 안의 숫자”다.  
CPU는 PC가 가리키는 상자만 명령으로 해석한다.

한 줄 명령의 전형적인 생김새(초기 기계):

```text
[할 일] + [어느 호수]
예: [더하라] [20]
```

“무엇을”과 “어디를”이 **한 장에 잉크로 붙어** 있다.  
같은 창고에 있으므로, 원리적으로는 그 잉크도 실행 중에 고칠 수 있다.  
그 문이 나중에 자기수정이 된다.

---

# 3장. 실행 순서는 누가 정하는가

주소 6, 7, 8에 명령을 나란히 두면 실행이 6→7→8처럼 보인다.  
그러나 **주소 숫자가 순서를 만드는 것이 아니다.**

순서를 정하는 것은 CPU 안의 작은 칸 **프로그램 카운터(PC)** 다.  
x86에서는 EIP/RIP라고도 부른다. 정체는 하나다.

> 지금 펼쳐 볼 레시피 상자의 번호.

매 박자 CPU가 하는 일:

```text
1. PC에 적힌 상자를 연다
2. 그 안의 명령을 실행한다
3. PC를 고친다
```

**기본 규칙:** 방금 읽은 줄 바로 다음으로 PC를 민다.  
한 명령이 상자 하나를 차지한다면 `PC ← PC + 1`.  
실제 x86은 명령 길이가 제각각이라 “방금 명령이 차지한 바이트 수”만큼 민다. 생각은 같다.

전원 직후 PC는 비어 있을 수 없다. 기계마다 약속된 시작 주소가 있거나, 안내 프로그램(부트로더·운영체제)이 “이 프로그램은 여기부터”라고 PC에 넣어 준다.

데이터 상자에 PC가 들어가면 CPU는 그 숫자를 명령으로 오해한다.  
레시피 구역과 재료 구역을 나누는 것은 프로그래머와 운영체제의 약속이다.

명령을 6호와 50호에 흩어 두고 6 다음이 50이 되게 하려면, 6 근처에 **“50으로 가라”** 를 넣어야 한다.  
보통은 실행하고 싶은 순서로 상자를 붙여 두므로, 초심자에게는 주소가 곧 순서처럼 보인다.

# 4장. 어셈블리를 처음부터

## 4.1 기계어와 어셈블리

CPU가 실제로 읽는 것은 `89 34 24` 같은 **기계어 바이트**다.  
사람은 그걸 못 읽으니, 짧은 영어 약어로 옮겨 적는다. 그것이 **어셈블리**.

```text
기계어:    01 06
어셈블리:  add eax, [esi]
뜻:        esi가 가리키는 상자 안을 eax에 더하라
```

어셈블러라는 프로그램이 왼쪽 글을 오른쪽 바이트로 바꾼다.  
이 노트에서 어셈블리는 “상자 작업을 줄여 쓴 메모”일 뿐이다.

## 4.2 레지스터: CPU 안의 손바닥 상자

RAM 상자는 많고 상대적으로 느리다.  
CPU 칩 안에는 이름 붙은 **아주 빠른 상자**가 몇 개 있다. 이것이 레지스터.

이 노트에서 쓰는 x86-32 이름:

| 이름 | 이 노트에서의 역할 |
|------|-------------------|
| `eax` | 계산 결과, 합계를 쥐는 손 |
| `esi` | “지금 열 호수”를 쥐는 손 (메모지를 손에 든 것) |
| `eip` | PC. 지금 읽을 명령의 주소. 보통 직접 안 건드린다 |

레지스터는 창고 호수가 아니라 **CPU 안의 별도 칸**이다.  
`eax`에 7이 있다는 것은 “합계 상자가 7”과 비슷하지만, 훨씬 빨리 읽고 쓴다.

## 4.3 대괄호 `[]` 하나가 전부다

x86 어셈블리에서 가장 중요한 기호는 대괄호다.

```text
eax          손바닥 칸 eax 안의 숫자 그 자체
[eax]        eax에 적힌 숫자를 호수로 알고, 그 RAM 상자를 연다
```

일상어:

```text
eax     = 메모지에 적힌 호수
[eax]   = 그 호수 문을 열고 본 내용
```

이 한 겹이 포인터의 기계어 형태다.

## 4.4 이 노트에서 쓰는 명령 여덟 개

문법은 Intel 식(목적지가 왼쪽)이다.

### `mov` — 옮겨 담기

```asm
mov eax, 0          ; eax라는 손에 0을 쥐어라
mov eax, esi        ; esi에 있는 숫자를 eax에 복사
mov eax, [esi]      ; esi가 가리키는 RAM 상자 안을 eax에 복사
mov [esi], eax      ; eax의 숫자를 esi가 가리키는 RAM 상자에 저장
```

`;` 오른쪽은 주석이다. CPU는 읽지 않는다.

### `add` — 더하기

```asm
add eax, 1          ; eax ← eax + 1
add eax, [esi]      ; eax ← eax + (esi가 가리키는 상자 안)
add dword [label], 4 ; label 위치의 4바이트 숫자에 4를 더함
```

`dword`는 “4바이트짜리 숫자로 취급하라”는 표시다.  
지금은 “상자 한 칸이 정수 하나”라고만 기억하면 된다.

### `inc` — 1 증가

```asm
inc esi             ; esi ← esi + 1
inc dword [box]     ; box 상자 안 ← 그 값 + 1
```

`add esi, 1`과 같다. 짧은 표기다.

### `cmp` — 비교만 하고 기억

```asm
cmp esi, 22         ; esi와 22를 비교한다. esi 값은 안 바뀐다.
```

비교 결과는 CPU 안의 **플래그**(맞다/작다/같다 같은 작은 표시)에만 남는다.  
바로 다음 점프 명령이 그 표시를 보고 뛸지 말지 정한다.

### `jmp` — 무조건 점프

```asm
jmp here            ; PC를 here라는 이름 위치로 덮어쓴다
```

### `jne` / `jl` / `jb` — 조건부 점프

```asm
jne here            ; 방금 비교가 “같지 않음”이면 here로
jl  here            ; 부호 있는 정수로 “더 작으면” here로
jb  here            ; 주소처럼 “아래면” here로 (unsigned)
```

`jne` = Jump if Not Equal.

### 라벨 — 상자 번호 대신 붙이는 이름

```asm
here:
    add eax, [esi]
    jmp here
```

`here:`는 명령이 아니다.  
“이 줄이 놓인 주소에 `here`라는 이름을 붙인다.”  
어셈블러가 실제 숫자 주소로 바꾼다. 사람이 6호, 7호를 외우지 않아도 되게 한다.

### `nop` — 아무것도 하지 않음

한 칸을 차지하고 PC만 다음으로 민다. 자리 메우기나 패치 지점에 쓴다.

# 5장. 점프와 goto

점프는 PC를 덮어쓰는 일이다.

```asm
    jmp there       ; 무조건 there로
there:
    mov eax, 0
```

고급 언어의 `goto there;` 가 바로 `jmp there` 다.

조건이 붙으면:

```asm
    cmp esi, 22
    jne there       ; esi ≠ 22 이면 there로, 아니면 다음 줄
```

기계의 제어는 거의 전부 이 점프다.

| 언어에 보이는 것 | 기계가 하는 것 |
|--|--|
| 차례대로 | 점프 없음, PC를 다음 줄로 |
| `if` | 앞으로 건너뛰는 조건부 점프 |
| `while` / `for` | 검사 + 뒤로 점프 |
| `break` | 루프 끝 라벨로 점프 |
| `return` | 돌아온 주소로 점프 |
| `goto` | 포장 없는 `jmp` |

`goto`가 미움을 받는 이유는 점프가 존재해서가 아니라, **아무 줄에나 착지**해서 글의 모양과 실행 순서가 어긋나기 때문이다.  
`while`은 같은 점프를 “이 블록 안에서만” 쓰게 가둔다.  
컴파일하면 결국 다시 `jmp`/`jne`가 된다. CPU의 점프가 사라지는 것은 아니다.

---

# 6장. 루프는 점프의 응용이다

기계 바닥에 “반복하라”는 마법은 보통 없다. 루프는 패턴이다.

```text
① 몸통
② 계속할지 검사
③ 계속이면 ①로 점프
```

가장 작은 무한 루프:

```asm
spin:
    jmp spin        ; PC를 자기 자신으로 덮어쓴다
```

합산이 되려면 점프 사이에 **상태가 달라져야** 한다.

```asm
; 잘못된 루프: 점프는 되지만 늘 같은 상자만 연다
    mov eax, 0
bad:
    add eax, [20]   ; 언제나 20호만 더한다
    jmp bad
```

점프는 성공한다. 목록 순회는 실패한다.

일반 법칙:

> 같은 레시피 줄로 돌아왔을 때 세계 상태가 달라져 있어야 이야기가 진행된다.

상태가 달라지는 길:

1. 여는 주소가 달라진다 (20호 다음 21호) — 순회
2. 같은 주소의 내용이 달라진다 (외부 신호) — 대기
3. 횟수·합계 메모가 달라진다 — N번 반복

아무것도 안 변하면 무한 반복이거나 버그다.

두 층을 섞지 말 것:

```text
층 1. 레시피 위치 : 늘 loop 라벨로 점프   ← 뼈대
층 2. 재료/상태   : 20호 다음 21호        ← 의미
```

“돌아올 때마다 다른 상자를 열어야 한다”는 말은 **목록 순회**를 겨냥한 것이다.  
대기 루프는 같은 상자를 열어도 된다. 그 안의 미래가 바뀌기를 기다린다.

# 7장. 왜 자기수정이 나왔는가

사람이 원하는 글:

```text
반복:
    이번 상자를 더하라
    다음 상자로 가라
```

“이번 상자 번호”를 적어 둘 메모지가 없던 기계가 있었다.  
인덱스 레지스터도, `[레지스터]` 주소 방식도 없었다.  
명령 쪽지에만 주소가 잉크로 박혀 있었다.

선택지:

1. `add [20]`, `add [21]`, … 를 수천 줄 적는다
2. 한 줄만 두고, 실행 중에 그 줄의 주소 칸을 고친다

2번이 **자기수정 코드(Self-Modifying Code, SMC)** 다.

요리책 비유:

```text
【3쪽】 선반 ___ 호의 재료를 넣어라
【4쪽】 3쪽 빈칸에 1을 더해 다시 적어라
【5쪽】 끝이 아니면 3쪽으로 가라
```

같은 3쪽을 반복해 읽지만, 읽을 때마다 3쪽 글자가 다르다.

```text
[자기수정 방식: 레시피 자체의 잉크를 긁어고친다]
┌────────────────────────────────────────────────────────┐
│ CPU (일꾼)                                             │
│   1. [주소 6]의 잉크를 긁어 '20' → '21'로 고쳐 쓴다   │
│   2. 고쳐진 명령(add [21])을 실행하여 21호를 연다       │
└───────────┬────────────────────────────────────────────┘
            │ 잉크 수정 (명령 파괴)
            ▼
┌─────────────────────────┐         ┌────────────────────┐
│ [주소 6] 코드 영역      │ ──────▶ │ [주소 21] 데이터   │
│ "add [21]" (변질된 코드)│ (읽기)  │ 재료: 3            │
└─────────────────────────┘         └────────────────────┘

[포인터 방식: 레시피는 불변, 별도 메모지만 고친다]
┌────────────────────────────────────────────────────────┐
│ CPU (일꾼)                                             │
│   1. [주소 3] 메모지의 숫자를 20 → 21로 바꾼다         │
│   2. 고정된 명령(add [*p])을 보며 메모지(21호)를 연다  │
└───────────┬────────────────────────────────────────────┘
            │ 메모지 값만 수정 (명령 보존)
            ▼
┌─────────────────────────┐         ┌────────────────────┐
│ [주소 3] 메모지 (포인터)│ ──────▶ │ [주소 21] 데이터   │
│ 값: 21 (가리키는 곳)    │ (간접)  │ 재료: 3            │
└─────────────────────────┘         └────────────────────┘
```

1950년대 IBM 701, 초기 EDSAC 등이 배열을 이렇게 훑었다.  
인덱스 레지스터(맨체스터 B레지스터, 1949)가 생기기 전의 표준 우회였다.

<div class="callout-box info">
  <div class="callout-title">💡 역사 속의 자기수정: 휠러 점프 (Wheeler Jump)</div>
  <p>1949년 케임브리지 대학교의 데이비드 휠러(David Wheeler)는 세계 최초의 실용 저장 프로그램 컴퓨터 EDSAC에서 서브루틴(함수) 호출 기법을 고안했습니다. 당시 하드웨어에는 함수가 끝나고 돌아갈 주소를 저장할 '스택(Stack)'이나 전용 레지스터가 없었습니다. 그래서 호출자가 함수를 호출하기 직전, 서브루틴 맨 끝에 위치한 <code>jmp</code> 명령의 주소 필드에 "내가 돌아갈 복귀 주소"를 직접 덮어쓰는 자기수정 코드를 사용했습니다. 이를 <strong>휠러 점프</strong>라고 부르며, 초기 소프트웨어 역사에서 가장 유명한 자기수정의 사례 중 하나입니다.</p>

# 8장. 슬로모션 — 숫자 두 개

재료:

- 주소 20: `7`
- 주소 21: `3`
- 목표 합: \(7 + 3 = 10\)
- 끝 표지 주소: `22`

아래는 **한 명령이 메모리 한 칸**이라고 단순화한 가상 기계다.  
실제 x86은 한 명령이 여러 바이트를 먹는다. 생각은 같다.

## 8.1 자기수정 버전 (가상 기계)

창고 배치:

```text
주소 4 : 합계 = 0
주소 6 : add [20]          ← 이 줄의 20만 바뀐다
주소 7 : 6호의 주소 칸에 +1
주소 8 : 6호의 주소 칸이 22가 아니면 6으로 점프
주소 9 : 끝
주소 20: 7
주소 21: 3
```

가상 어셈블리:

```asm
    mov  [4], 0            ; 합계 = 0
    mov  [6], template     ; 6호에 "add [20]" 을 심는다 (이미 심어 두었다고 보자)

loop:
    ; ----- 주소 6 : 매 바퀴 글자가 바뀌는 줄 -----
    add  [4], [20]         ; 처음엔 [20], 다음에는 [21] ...
                           ; ↑ 이 줄의 '20' 주소 필드가 바로 수정 대상(patch_addr)

    inc  dword [loop+주소칸] ; 6호 명령의 주소 필드 +1

    cmp  dword [loop+주소칸], 22
    jne  loop
    ; 끝
```

박자표:

| 박자 | PC | 실행 | 합계(4) | **6호 명령(변질)** | 다음 PC |
|:---:|:---:|:---|:---:|:---:|:---:|
| 1 | 6 | 20호의 7을 더함 | 0→**7** | `add [20]` | 7 |
| 2 | 7 | 주소 칸 +1 | 7 | **`add [21]`** | 8 |
| 3 | 8 | 21≠22, 점프 | 7 | `add [21]` | **6** |
| 4 | 6 | 21호의 3을 더함 | 7→**10** | `add [21]` | 7 |
| 5 | 7 | 주소 칸 +1 | 10 | **`add [22]`** | 8 |
| 6 | 8 | 22=22, 점프 안 함 | 10 | `add [22]` | 9 |

끝난 뒤 6호는 `add [22]` 로 남는다. 레시피가 원본이 아니다.  
재료 20, 21은 한 번도 내용이 바뀌지 않는다. 읽히기만 한다.

## 8.2 포인터 버전 (가상 기계)

창고 배치:

```text
주소 3 : 메모지 = 20
주소 4 : 합계 = 0
주소 6 : add [4], [[3]]    ← 글자 영원히 고정
주소 7 : 3호 메모지 +1
주소 8 : 3호 메모지가 22가 아니면 6으로 점프
주소 9 : 끝
```

가상 어셈블리:

```asm
    mov  [3], 20           ; 3호(메모지) = 20
    mov  [4], 0            ; 4호(합계) = 0

loop:
    ; ----- 주소 6 : 글자가 영원히 고정된 줄 -----
    add  [4], [[3]]        ; 4호에 [3호 메모지가 가리키는 상자 안]을 더함
    inc  dword [3]         ; 3호 메모지의 숫자 +1
    cmp  dword [3], 22     ; 메모지가 22에 닿았는가?
    jne  loop
    ; 끝
```

박자표:

| 박자 | PC | 실행 | 합계(4) | **메모지(3)** | **6호 명령(불변)** | 다음 PC |
|:---:|:---:|:---|:---:|:---:|:---:|:---:|
| 1 | 6 | 3호가 가리키는 20호의 7을 더함 | 0→**7** | 20 | `add [4], [[3]]` | 7 |
| 2 | 7 | 3호 메모지 +1 | 7 | **21** | `add [4], [[3]]` | 8 |
| 3 | 8 | 3호(21)≠22, 점프 | 7 | 21 | `add [4], [[3]]` | **6** |
| 4 | 6 | 3호가 가리키는 21호의 3을 더함 | 7→**10** | 21 | `add [4], [[3]]` | 7 |
| 5 | 7 | 3호 메모지 +1 | 10 | **22** | `add [4], [[3]]` | 8 |
| 6 | 8 | 3호(22)=22, 점프 안 함 | 10 | 22 | `add [4], [[3]]` | 9 |

점프 경로 6→7→8→6→…→9 는 같다.  
박자 2와 5에서 바뀌는 것이 6호가 아니라 3호 메모지다.  
끝난 뒤에도 6호 글자는 `add [4], [[3]]` 원본 그대로다.

# 9장. 실제 x86으로 옮기기

가상 기계를 떠나, 지금 PC에서 흔히 보는 32비트 x86 문법으로 같은 일을 적는다.  
한 명령이 여러 바이트인 점만 추가하면 된다.

## 9.1 먼저, 포인터 버전이 정석이다

```asm
; 데이터
nums:   dd 7, 3            ; dd = 4바이트 정수 두 개. 주소가 연속
                           ; nums     → 7
                           ; nums+4   → 3
endn:                      ; 끝 표지. 라벨만 있고 값은 없음
                           ; 주소가 "3 다음 칸"

; 코드
    xor  eax, eax          ; eax = 0  (합계). xor 자기 자신은 0으로 만드는 관용구
    mov  esi, nums         ; esi = 첫 원소의 주소. 손에 메모지를 쥔다

loop1:
    add  eax, [esi]        ; 합계 += *esi
    add  esi, 4            ; 다음 정수로. 정수가 4바이트이므로 +4
    cmp  esi, endn         ; 끝에 닿았나
    jne  loop1             ; 아니면 몸통으로
    ; 여기 오면 eax == 10
```

해설:

- `nums:` 는 7이 놓인 주소의 이름이다.
- `dd 7, 3` 은 그 자리에 4바이트 7, 그 옆에 4바이트 3을 배치하라는 뜻이다.
- `esi`가 포인터다. “지금 열 호수”를 손에 쥐고 있다.
- `[esi]`가 “그 호수를 열어라”다.
- `add esi, 4`가 “다음 상자로 가라”다. 명령 글자는 안 변한다.
- `jne loop1`이 루프의 뼈대(뒤로 점프)다.

C로 쓰면 이것이다.

```c
int nums[] = {7, 3};
int *p = nums;
int *end = nums + 2;
int sum = 0;
while (p < end) {
    sum += *p;
    p++;
}
```

C의 `p++`는 정수 포인터이므로 컴파일러가 `+4`로 바꾼다.

## 9.2 자기수정 버전 — 명령의 주소 칸을 고친다

같은 합산을, 일부러 1950년대 방식으로 적는다.  
**학습용이다. 현대 OS에서는 실행 코드를 쓰지 못하게 막거나, 캐시 때문에 기대한 대로 안 움직일 수 있다.**

원리는 이것이다.

```asm
; 실행될 한 줄
patch:
    add  eax, [nums]       ; 처음엔 nums, 다음에는 nums+4 ...

; 위 줄에서 "nums"가 적힌 바이트 위치를 찾아
; 그 숫자에 4를 더한다
```

x86에서 `add eax, [변위]` 형태는 대략 이런 바이트열이다. (환경에 따라 접두어가 붙을 수 있다.)

```text
03 05  xx xx xx xx
│  │   └─ 32비트 절대 주소 (여기가 빈칸)
│  └──── ModR/M
└─────── opcode (add r32, r/m32)
```

고칠 곳은 뒤의 4바이트 주소다.

개념 코드:

```asm
    xor  eax, eax
    mov  dword [addr_field], nums     ; 시작 주소로 빈칸 초기화

loop2:
patch:
    add  eax, [nums]                  ; 이 줄의 주소 필드가 매 바퀴 바뀜
addr_field equ patch + 2              ; "opcode+ModR/M 다음이 주소다"라는 약속
                                      ; 실제 오프셋은 어셈블러/기계에 따라 확인해야 함

    add  dword [addr_field], 4        ; 빈칸 += 4
    cmp  dword [addr_field], endn
    jne  loop2
```

`equ`는 “이 이름은 저 숫자와 같다”는 조립 시점 별명이다.  
`patch + 2`는 “`patch` 라벨에서 2바이트 뒤”를 가리킨다.

실행 중 메모리:

```text
처음  patch 줄:   add eax, [nums]
한 바퀴 후:       add eax, [nums+4]
그다음:           add eax, [endn]   → 종료 비교에 걸림
```

같은 `loop2`로 점프해 돌아오지만, `patch` 줄의 기계어 숫자가 달라져 있다.

### 6502 / 8비트에서 더 잘 보이는 형태

주소가 명령 바로 뒤에 붙는 8비트 기계는 빈칸이 눈에 보인다.

```asm
; 6502 느낌. $2000 부터 $2001 까지 더한다고 가정 (8비트)
    LDA #$00            ; A레지스터 = 0 (합계)
LOOP:
STO: ADC $2000          ; 처음엔 $2000, 다음엔 $2001
    INC STO+1           ; ADC 명령의 하위 주소 바이트 +1
    LDA STO+1
    CMP #$02            ; $2002 가 되면 끝 (예)
    BNE LOOP
```

`STO+1`은 “`STO` 라벨 다음 1바이트”, 즉 **명령의 주소 필드**다.  
`INC`가 레시피 빈칸을 고친다.

## 9.3 두 버전의 기계어 차이, 한 줄로

```text
포인터:     add eax, [esi]     명령 바이트는 평생 동일. esi만 변함
자기수정:   add eax, [????]    ???? 가 적힌 바이트가 변함
```

점프(`jne loop`)는 둘 다 같다.

# 10장. 자기수정이 악몽인 이유

1. **제어와 데이터가 한 종이에 섞인다**  
   “지금 몇 호인가”가 명령 비트에 숨는다. 덤프를 봐도 상태가 안 보인다.

2. **다시 실행이 안 된다**  
   중간에서 끊기면 빈칸이 `nums+4`로 남는다. 처음부터 다시 돌리면 앞 원소를 건너뛴다.  
   루틴 끝에 빈칸을 원상복구하는 코드가 따로 필요하다.

3. **동시에 못 쓴다**  
   두 실행이 한 명령 줄을 같이 고치면 서로의 주소를 짓밟는다.

4. **ROM / 플래시에 못 올린다**  
   명령 영역을 쓸 수 있어야 한다. 읽기 전용 펌웨어와 충돌한다.

5. **버그가 책을 파괴한다**  
   주소 필드에 잘못된 값을 더하면 opcode까지 캐리가 넘어가 `add`가 `jmp`가 될 수 있다.

6. **현대 CPU는 명령을 미리 읽는다**  
   I-cache와 파이프라인에 옛 바이트가 남을 수 있다. x86은 같은 선형 주소로 고치면 어느 정도 맞춰 주지만, 파이프라인을 비우는 대가를 치른다. ARM 계열은 캐시 동기화를 직접 해야 한다.

7. **W^X (Write XOR Execute) / NX 보안 정책**  
   현대 운영체제는 악의적인 셸코드 삽입 공격을 막기 위해 **W^X (쓰기 권한과 실행 권한을 동시에 주지 않음)** 정책과 NX(No-Execute) / DEP(Data Execution Prevention) 비트를 강제합니다.  
   즉, 코드가 있는 메모리 페이지는 읽기/실행만 가능하고 쓰기가 금지되며, 데이터를 쓰는 페이지는 실행이 불가능합니다.  
   따라서 일반적인 사용자 프로그램에서 자기수정 코드를 실행하려 하면 운영체제가 즉시 세그멘테이션 폴트(Segmentation Fault / Access Violation)를 일으켜 프로그램을 강제 종료시킵니다.  
   *참고: V8(자바스크립트), JVM HotSpot 등 런타임에 기계어를 생성하는 **JIT(Just-In-Time) 컴파일러**는 `VirtualProtect`(Windows)나 `mprotect`(Linux/macOS) 시스템 호출을 사용해 일시적으로 메모리 권한을 쓰기 가능으로 바꾼 뒤 코드를 작성하고, 다시 실행 전용으로 되돌리는 엄격한 절차를 거칩니다.*

# 11장. 포인터와 레지스터

## 질문

포인터가 생겼다는 것은 전용 레지스터가 생겼다는 뜻인가?

## 답

반만 맞다.

| | 무엇인가 |
|--|--|
| 포인터 | 상자 번호를 값처럼 저장·계산·전달한다는 **규칙** |
| 레지스터 | 그 숫자를 올려두는 CPU 안의 **빠른 손** |

같은 포인터 `p`가 사는 곳:

```text
① CPU 레지스터   esi에 들어 있음     ← 9.1절
② RAM 상자       [3]에 들어 있음     ← 8.2절
③ 계산 도중에만 존재
```

C의 `int *p`는 “주소가 담긴 변수”다. 컴파일러가 여유 있으면 ①, 없으면 ②.

1949년 맨체스터 **B레지스터(인덱스 레지스터)** 가 한 일:

```text
실제 주소 = 명령에 적힌 기본 번호 + B칸의 숫자
명령 글자는 불변
```

자기수정이 하던 “빈칸 고치기”를, 실행 순간의 덧셈으로 바꿨다.

레지스터가 없어도 포인터는 흉내 낼 수 있다.

```asm
; 메모리 간접. p는 RAM의 3호에 있다
    mov  eax, [3]        ; 3호에서 호수를 꺼낸다
    add  ebx, [eax]      ; 그 호수를 연다
    add  dword [3], 4    ; 메모지 +4
```

전용 포인터 레지스터는 없다. 느릴 뿐이다.

현대 x86:

```text
아무 범용 레지스터나
그 숫자가 [칸]에 쓰이면 그것이 포인터
```

손이 곧 책갈피는 아니다.  
손이 생기면서 책갈피라는 생각이 **싸게, 안전하게** 쓰이게 된 것이다.

# 12장. 역사

층마다 발명자가 다르다.

| 층 | 시기 | 내용 |
|---|---|---|
| 기계 | 1949 맨체스터 | 인덱스 레지스터. 명령 수정 없이 주소 계산 |
| 어셈블리 | 1950년대 | 주소는 숫자. 더하고 그 번호로 연다 |
| 서구 밖 언어 | 1955 Kateryna Yushchenko, Address | 간접 주소, 주소의 주소 |
| 고급 언어 변수 | 1964–67 Harold Lawson, PL/I | IEEE가 “포인터 변수”로 공인한 줄기 |
| 참조 | 1965 C. A. R. Hoare | 레코드 참조, 널 |
| 단어=주소 | 1966–67 Martin Richards, BCPL | 모든 값이 기계 단어 |
| 대중적 형태 | 1971–73 Dennis Ritchie, C | `*`, `&`, `p++` |

“한 사람이 포인터를 발명했다”는 말은 층을 섞는다.  
Lawson은 **범용 고급 언어의 포인터 변수**로 가장 많이 적힌 이름이다.

하드웨어 변경이 언어 도입의 필수였나? **논리적으로는 아니다.**

컴파일러는 메모리 간접으로, 최악의 경우 자기수정을 몰래 생성해서 `*p`를 구현할 수 있다.  
하드웨어가 한 일은 가능하게 만든 것이 아니라 **싸게, 안전하게, 자기수정 없이** 만든 것이다.  
C의 `*p++`가 PDP-11 주소 방식과 잘 맞았던 것은 유혹이지 필수 조건이 아니다.

# 13장. 한 창고에 모두 올려놓기

같은 합산 루프를 네 층으로 보면 역할이 갈린다.

```text
goto / jmp      다음에 펼칠 레시피 줄 (PC)
포인터          다음에 열 재료 호수 (값)
레지스터        그 호수를 쥐는 손 (위치)
자기수정        레시피 글자 자체를 고침 (최후의 수단)
```

포인터가 없던 세계의 재앙 한 가지는 이제 이렇게 읽힌다.

> 점프는 있었다. 같은 줄로 돌아올 수 있었다.  
> 없던 것은 “이번엔 몇 호인가”를 명령 밖에 둘 자리였다.  
> 그래서 명령 빈칸을 고쳤다.  
> 포인터는 그 빈칸을 레시피에서 꺼내 메모지로 만든 것이다.

공식:

```text
실행 순서     = PC의 갱신
점프 / goto   = PC 덮어쓰기
루프          = 뒷점프 + 변하는 상태 + 멈출 조건
자기수정      = 상태를 명령 문장 속에 둔다
포인터        = 상태를 주소 값으로 꺼낸다
레지스터      = 그 값을 빠르게 쥐는 손
```

# 부록 A. 어셈블리 치트시트 (이 노트 범위)

```text
mov  A, B        A ← B
add  A, B        A ← A + B
inc  A           A ← A + 1
xor  A, A        A ← 0
cmp  A, B        A와 B 비교. A는 안 바뀜
jmp  L           PC ← L
jne  L           같지 않으면 PC ← L
[A]              A를 호수로 알고 RAM을 연다
label:           이 주소의 별명
dd   n           여기에 4바이트 정수 n을 배치
; 주석
```

읽기 연습:

```asm
add eax, [esi]     eax에, esi가 가리키는 상자 안을 더하라
add esi, 4         esi가 쥐고 있는 호수를 4 올려라
jne loop           방금 비교가 불일치면 loop로 가라
```
