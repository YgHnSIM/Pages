## 결론부터

**에이전트를 똑똑하게 만드는 법은 더 긴 프롬프트가 아니라, 서로 안 읽는 일은 동시에 시키고 진짜로 기대야 하는 지점에서만 모이게 하는 것이다.**

에이전트 컨트롤은 “AI를 여러 명 고용하는 기술”이 아니다. **기다릴 이유 없는 대기를 지우고, 판단이 필요한 자리에만 머리를 쓰는 기술**이다. 대부분의 멀티스텝 에이전트는 한 줄 사슬이다. 이를 **그래프(노드+간선)** 로 다시 그리면 병렬·검증·비용이 달라진다.

한 줄로 더 줄이면 이렇다.

> 조율은 코드(토큰 0). 판단만 모델. 가짜 화살표를 먼저 지워라.

## 1. 프레임을 한 칸 옮긴다

프롬프트·루프·하네스를 잘 다루면서도 **일의 모양** 자체를 못 보는 경우가 많다. 식당에 비유하면 표로 한눈에 들어온다.

| 비유 | 의미 | 에이전트에서 |
| --- | --- | --- |
| **주문 쪽지(프롬프트)** | 손님의 한 문장 | “이 파일 요약해” 같은 지시 |
| **주방 순환(루프)** | 같은 사람이 볶고·간보고·다시 볶기 | 한 에이전트의 think→act→observe |
| **주방 바닥·도구(하네스)** | 불·칼·타이머·위생 규칙 | 실행 환경, 도구, 권한, 상태 이어 주기 |
| **동선(그래프)** | 누가 무엇을 먼저·동시에·모아서 하는지 | 노드(일) + 간선(데이터 의존) |

| 단어 | 흔한 착각 | 옮긴 자리 |
| --- | --- | --- |
| **프롬프트** | 일을 “더 똑똑하게” 만드는 마법 문장 | **문장** — 한 노드에 넣는 지시 |
| **루프** | 에이전트가 알아서 끝나는 전부 | **순환** — 한 노드 안의 반복 |
| **하네스** | 모델 이름 옆에 붙는 장식 | **바닥** — 도구·권한·상태가 서는 자리 |
| **일의 형태** | “스텝 1, 2, 3…” 체크리스트 | **그래프** — 무엇이 무엇을 먹는지 |

바이브 코딩의 강점은 한 사람과 한 컨텍스트로 **흐름을 타는 것**이다. 함대는 그 강점을 버리는 기술이 아니라, **한 컨텍스트가 감당 못 하는 폭**이 생겼을 때만 쓰는 확장이다.

<div class="callout-box info">
  <div class="callout-title">함대가 사는 것</div>
  <p>그래프는 <strong>폭(breadth)</strong>을 산다. 더 좋은 판단력 자체를 공짜로 주지 않는다. 각 단계가 앞 단계의 전체 그림을 꼭 읽어야 하면, 나눈 순간 같은 답을 <strong>더 비싸고 늦게</strong> 받게 된다.</p>
</div>

## 2. 노드와 간선 — 딱 두 가지만 기억

그래프에는 정확히 두 종류만 있다.

- **노드**: 범위가 정해진 일 하나. 입력 → (한 가지 일) → 모양이 있는 출력.
- **간선**: 의존성. “이쪽 출력이 저쪽 입력으로 **실제로** 흘러간다”는 약속.

다이어그램으로 그리면 박스가 `agent()` 한 번이고, 화살표는 **앞 호출의 return이 다음 프롬프트 변수로 들어가는 자리**다. 변수가 안 건너가면 화살표를 그릴 수 없다. 그릴 수 없으면 **독립**이다. 독립이면 줄 세울 이유가 없다.

조율(누가 언제 뜨는지, 결과를 어디에 모으는지)은 **코드**에 둔다. 코드는 모델 토큰을 거의 안 먹는다. “다음에 무엇을 시킬까”를 또 다른 에이전트에게 맡기면, 배관비까지 시급을 주는 꼴이다.

## 3. 가짜 간선 — “그리고 나서”의 함정

가장 흔한 실수는 **접속사**를 **의존성**으로 착각하는 것이다.

| 말 | 진짜 간선? | 이유 |
| --- | --- | --- |
| “이 파일 요약하고, **그리고 나서** 날씨 알려줘” | 없음 | 날씨는 요약을 안 읽음 |
| “A 폴더 훑고, **이어서** B 폴더 훑어” | 대개 없음 | 서로 결과를 안 먹음 |
| “조사 결과들을 **모아서** 순위 매겨” | **있음** | 순위는 전체 집합이 필요 |
| “버그 설명 → 재현 스크립트 작성” | **있음** | 스크립트가 설명을 입력으로 씀 |

규칙은 단순하다.

> 매 “그리고 나서”마다 묻는다. **다음 단계가 이전 출력을 읽는가?**  
> 아니면 그 대기는 버린 시간이다.

## 4. 선형 스크립트는 이미 그래프다 — 다만 퇴화한 형태

“A 하고, B 하고, C 하고, D”는 이미 그래프다. 가지가 없는 **사슬**일 뿐이다. 각 노드에 들어오는 화살표·나가는 화살표가 하나씩뿐이라, C가 막히면 D는 영영 없고 A의 결과는 상류에 묶인다.

첫 실무 기술은 도구를 사는 것이 아니라 **사슬을 다시 그리는 것**이다. 화살표마다 3절의 질문을 던진다. 데이터 없는 화살표를 자르면 사슬이 **넓어**진다. 독립 노드 여러 개가 동시에 돌고, **전부**가 필요한 한 노드만 아래에서 받는다.

## 5. 노드 계약 — 입력 / 한 일 / 모양 있는 출력

병렬로 못 돌리는 노드의 공통점은 **계약을 말로만** 둔다는 것이다.

좋은 노드 계약:

1. **입력**은 명시적으로 넘긴다. 공유 채팅 창에 “알아서 보겠지”를 가정하지 않는다.
2. **일은 하나**. “조사하고 요약하고 평가까지”는 노드 세 개다.
3. **출력은 형태**가 있다. 가능하면 스키마(필드·enum·필수값)로 검증한다.

형태 없는 출력은 노드가 아니라 **대화**다. 다음 노드가 추측 파싱을 하게 되면 그래프는 금세 부서진다.

```text
개념 스케치 (스키마로 출력을 고정)

ITEM = {
  title, url, impact ∈ {high, mid, low}
}

결과 = agent(출처.prompt, { schema: ITEM })
→ 실패 시 재시도 / 성공 시 다음 간선이 필드를 그대로 소비
```

## 7. 부채꼴로 펼치고, 필요할 때만 모은다

서로 안 읽는 N개가 있으면 줄 세우지 않는다. **동시에** 펼친다. 개념적으로는 `parallel()`: 독립 작업 배열을 한 번에 띄우고, 결과를 배열로 돌려받는다.

실무에서 자주 쓰는 두 디테일:

- **배리어(fan-in)**: 다음 단계가 **전체 집합**을 봐야 할 때만 전원이 끝나길 기다린다.

### parallel vs pipeline

| | **parallel(배리어)** | **pipeline(흐르기)** |
| --- | --- | --- |
| 대기 | 가장 느린 노드가 끝나야 다음 단계 | 항목마다 독립으로 다음 단계 진입 |
| 쓸 때 | 중복 제거·전체 비교·조기 종료처럼 **집합**이 필요 | 항목 간 의존이 없을 때(기본값에 가깝다) |
| 비용 | 빠른 일이 느린 일 뒤에 줄 섬 | 빠른 일은 먼저 끝남 |

“단계가 분리돼 보여서 깔끔하다”는 배리어 이유가 아니다. **분리 ≠ 동기화**.

## 8. 실행 중에 간선을 고른다 (동적 워크플로)

그래프가 항상 고정일 필요는 없다. 라우터 노드가 결과를 보고 길을 고른다. “위험도 높음 → 파일별 감사 함대 / 낮음 → 빠른 한 방 리뷰”처럼.

핵심 분할은 이것이다.

| 층 | 누가 | 하는 일 |
| --- | --- | --- |
| **판단** | 모델 | “이게 뭔가?” (분류·위험도·요약) |
| **라우팅** | 코드 | “그럼 어디 간선으로?” (`if` / `switch`) |

모델이 “감으로 감사를 스킵”하게 두지 않는다. 스킵이 필요하면 **그래프에 적힌 간선**이어야 한다. 같은 분류면 같은 길로 가는 **결정성**이 장점이다.

일의 모양이 실행마다 바뀌면, 사람이 매번 상자를 그리기보다 **목표를 설명하고 오케스트레이션 스크립트를 그리게** 하는 쪽이 맞다. 잘 나온 스크립트는 저장·이름 호출·재실행이 가능하게 둔다. (제품마다 메뉴 이름은 다르지만, “이번 실행 전용 그래프를 코드로 남긴다”는 아이디어는 같다.)

---

## 9. 모델 티어링 — 모든 노드에 최고 모델을 두지 마라

그래프를 그리면 한눈에 보인다. **지루하고 반복인 노드**와 **진짜 판단이 모이는 노드**가 다르다.

```text
  추출·분류·형식 맞추기     →  가벼운 모델 (폭을 값싸게)
  렌즈 검증                →  중간~규칙 엄격
  합성·판결·최종 보고서     →  상위 모델 (기준이 사는 자리)
```

세션 기본 모델을 함대 전체에 그대로 물리면, 큰 실행 한 번이 통째로 고가 요금이 된다. 반복 팬아웃만 낮추고 합성 노드만 올려도, **모양은 유지한 채** 청구서만 바뀐다.

> **비싼 모델은 기준이 걸린 자리에만.**

## 10. 적대적 검증 — 자기 채점 금지

그래프의 진짜 레버리지는 “에이전트 수”가 아니라, **결과가 아래로 내려가기 전에 죽이는 구조**다. 검증 노드는 간선 위에 앉아 발견을 공격한다. 살아남으면 통과, 아니면 최종본에 못 간다.

단단한 규칙 하나:

> **같은 에이전트에게 자기 시험을 채점시키지 마라.**  
> 틀린 자리에서 다시 보면, 같은 맹점이 대부분 안 보인다.

입문용 패턴 세 가지:

1. **적대적 검증**: 발견마다 독립 회의론자 N명을 띄워 반박하게 한다. 다수에 살아남은 것만 남긴다.
2. **렌즈 다양성**: 각각 다른 각도(정확성 / 보안 / 재현). 같은 질문을 N번 반복하는 것과 다르다.
3. **판정 패널**: 여러 초안을 다른 각도로 만들고, 심사위원을 병렬로 두어 점수한 뒤, 승자 위에 근접안의 장점을 이식해 합성한다.

## 11. 함대를 띄우지 말아야 할 때

반례를 먼저 외운다. 그래프는 폭을 살 뿐, 갈라지지 않는 일에 함대를 붙이면 **같은 답을 비싸게** 만든다.

| | **단일 에이전트(바이브의 본진)** | **함대(그래프)** |
| --- | --- | --- |
| 일의 모양 | 매 스텝이 직전 전체 맥락을 읽음 | 서로 안 읽는 덩어리로 **갈라짐** |
| 강점 | 흐름·여운·빠른 탐색 | 폭·격리·검증·비용 티어링 |
| 위험 | 컨텍스트 비대화, 한 줄 대기 | 배관 과다, 가짜 병렬, 검증 없는 폭주 |
| 질문 | “한 사람이 이어서 해도 되나?” | “어디서 가르고, 어디서만 모이나?” |

갈라지지 않으면 **한 명이 정답**이다. 남은 단계는 아껴도 된다.

## 12. 오늘 밤 5단계 연습

도구 설치보다 **종이(또는 빈 마크다운) 한 장**이면 된다.

1. **지금 쓰는 멀티스텝을 상자·화살표로만 그린다.** 프롬프트 문장을 상자 안에 길게 쓰지 말 것.
2. **화살표마다** “데이터가 건너가는가?”를 묻고, 가짜 간선을 지운다.
3. **독립 상자**에 동시 실행 표시를 친다. 모으는 상자는 “전체 집합이 필요할 때”만 남긴다.
4. **최종으로 내려가는 간선**에 검증자(다른 일꾼) 한 명을 얹는다. 자기 채점 금지.
5. **반복 상자**와 **판결 상자**에 모델 등급을 다르게 적어 본다.

### 체크리스트 (3개 이상 실패면 아직 사슬)

- 데이터 없는 간선을 지웠는가?
- 일이 정말 갈라지는가, 아니면 매 스텝이 직전 전체를 읽는가?
- 각 노드에 입력·한 일·형태 있는 출력이 있는가?
- flatMap/Set으로 될 일에 에이전트를 쓰고 있지 않은가?
- 집합이 필요 없는 배리어를 두고 있지 않은가?
- 검증 없이 최종본으로 가는 발견이 있는가?
- 검증자 둘이 같은 질문만 던지고 있지 않은가?
- 루프에 라운드 상한과 “본 것 전체” 기준 중복 제거가 있는가?
- 같은 파일을 쓰는 노드가 둘 이상인가?
- 반복 노드가 최고가 모델을 쓰고 있는가?
