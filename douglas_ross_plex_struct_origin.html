구조체(Struct)는 어떻게 발명되었는가 — 더글러스 로스의 플렉스(Plex)와 역인덱싱

배열밖에 없던 1950년대, 메모리 오프셋과 인스턴스화의 개념을 개척한 MIT의 역발상

#컴퓨터 과학사 #메모리 모델 #C/C++ #자료구조 #시스템 프로그래밍 #MIT

# 도입 — 너무나 당연해서 잊어버린 질문

현대 프로그래밍 언어로 코드를 작성하는 사람이라면 누구나 다음과 같은 형태의 코드를 자연스럽게 작성합니다.

c 
struct Point {
    int x;
    int y;
    const char *name;
};

struct Point p1;
p1.x = 10;
p1.y = 20;

서로 다른 타입의 데이터들(int, int, 포인터)을 하나의 이름 아래 묶어두고, 필요할 때마다 새로운 인스턴스를 메모리에 할당하며, 점(.) 연산자나 화살표(->) 연산자를 통해 특정 필드에 순식간에 접근합니다. C 언어의 struct, Rust의 구조체, Go의 type ... struct, C++과 Java의 class에 이르기까지, 현대 컴퓨팅 세계는 "관련된 이종(heterogeneous) 데이터를 한 덩어리로 묶어 다룬다"는 개념 위에 단단히 세워져 있습니다.

하지만 시간을 1950년대로 되돌려 보겠습니다. 당시 최첨단 진공관 컴퓨터와 초기 트랜지스터 컴퓨터 앞에 앉아 있던 세계 최고의 수학자들과 엔지니어들에게 위와 같은 개념을 설명한다면 어떤 반응이 돌아왔을까요?

"서로 다른 타입의 데이터를 하나로 묶는다고? 하나의 기준 주소에서 고정된 간격만 더해 개별 필드를 바로 꺼낸다고? 그런 발상을 도대체 왜, 어떻게 한다는 말인가?"

놀랍게도 1950년대 초중반까지 구조체(Struct)나 레코드(Record), 인스턴스화(Instantiation)라는 개념은 인류의 지적 지평선 위에 존재하지 않았습니다. 컴퓨터 메모리는 오직 동일한 타입의 숫자들을 늘어놓는 1차원 '배열(Array)'로서만 인식되던 시절이었습니다.

본 문서는 전설적인 게임 프로그래머이자 시스템 아키텍트인 케이시 무라토리(Casey Muratori)의 팟캐스트 대담을 뼈대로 삼고, 1961년 발표된 원전 논문과 역사적 사료를 보강하여 "구조체라는 거대한 패러다임이 어떻게 탄생했는가"를 추적하는 기술 사학적 탐구입니다.

핵심 명제: 역인덱싱(Reverse Indexing)

구조체(Struct)의 기원은 1956년 MIT 서보메커니즘 연구소의 더글러스 T. 로스(Douglas T. Ross)가 고안한 플렉스(Plex)다. 로스는 하드웨어 배열 인덱서의 기준점과 오프셋 역할을 정반대로 뒤집음으로써, 인류 최초로 '고정 오프셋을 통한 이종 데이터 번들링'과 '인스턴스화'의 문을 열었다.

# 1. 1950년대의 세계관 — 오직 '배열(Array)'뿐이던 시대

구조체의 탄생을 이해하려면 먼저 1950년대 컴퓨터 프로그래머들의 뇌리를 지배하고 있던 지배적 멘탈 모델을 이해해야 합니다.

당시 프로그래밍은 기계어 또는 초기 어셈블리어로 작성되었으며, 메모리는 그저 번호가 매겨진 워드(word)들의 선형적인 연속체였습니다. 데이터를 구조화하는 유일한 표준적인 방법은 배열(Array)이었습니다.

평문 
[ 전통적인 배열 모델 ]
Base Pointer (배열의 시작 주소, 고정)
     │
     ▼
┌─────────┬─────────┬─────────┬─────────┬─────────┐
│ arr[0]  │ arr[1]  │ arr[2]  │ arr[3]  │ arr[4]  │ ...
└─────────┴─────────┴─────────┴─────────┴─────────┘
  +0        +1*size   +2*size   +3*size   +4*size
     ───────► ───────► ───────► (가변 인덱스 i)

하드웨어 제조사들도 이에 맞춰 CPU에 배열 인덱싱 전용 레지스터와 명령어를 설계했습니다. 인덱스 계산 공식은 명확했습니다:

$\text{Address} = \text{Base} + (i \times \text{Size})$

여기서 주목해야 할 사고의 틀은 다음과 같습니다:

  1. 베이스 포인터(Base)는 고정되어 있다: 배열 arr의 시작 주소는 프로그램 실행 중 특정 지점에서 고정된 닻(anchor) 역할을 합니다.
  2. 오프셋(Index)은 유연하게 변한다: 반복문(loop)을 돌면서 $0, 1, 2, 3 \dots$으로 증가하는 인덱스를 더해 원소를 하나씩 순회합니다.
  3. 모든 원소는 동질(homogeneous)적이다: 배열의 모든 칸은 크기와 형태가 완전히 동일한 정수(integer)이거나 부동소수점 수여야만 했습니다.

# 여러 속성을 다루는 당시의 고육지책: 병렬 배열(Parallel Arrays)

만약 2차원 공간에 점(Point) 100개가 있고, 각 점마다 $X$ 좌표, $Y$ 좌표, 점의 번호(ID)를 저장해야 한다면 당시 엔지니어들은 어떻게 처리했을까요? 오늘날처럼 Point points[100];을 선언할 수 없었던 그들은 병렬 배열(Parallel Arrays)이라는 분산 구조를 썼습니다.

평문 
X_coords:  [ x0,   x1,   x2,   ...   x99  ]
Y_coords:  [ y0,   y1,   y2,   ...   y99  ]
Point_IDs: [ id0,  id1,  id2,  ...  id99  ]

$i$번째 점의 정보를 알고 싶다면 $X$ 배열의 $i$번째 방, $Y$ 배열의 $i$번째 방, $ID$ 배열의 $i$번째 방을 제각각 찾아가야 했습니다. 데이터가 서로 멀리 떨어진 메모리에 흩어져 있었고, 어떤 실체(Entity) 하나를 함수로 넘기거나 조작하려면 관련된 모든 배열의 주소와 인덱스를 줄줄이 꿰고 있어야 했습니다.

# 2. MIT 서보메커니즘 연구소와 수치제어(NC)의 도전

이러한 한계가 임계점에 도달한 곳이 바로 MIT 서보메커니즘 연구소(Servomechanisms Laboratory)였습니다.

1950년대 중반, 이 연구소는 미 공군(US Air Force)의 지원을 받아 현대 3D 프린팅과 CNC(컴퓨터 수치제어) 가공의 직계 조상이라 할 수 있는 APT(Automatically Programmed Tool) 프로젝트를 진행하고 있었습니다. 인간 조종사가 손으로 밀링 머신을 깎는 대신, 수학적 방정식과 기하학적 형상을 컴퓨터에 입력하면 기계 팔이 금속 블록을 자동으로 깎아 제트기 부품을 만들어내는 혁신적인 연구였습니다.

이 과제를 이끌던 핵심 인물이 바로 수학자이자 컴퓨터 과학자였던 더글러스 T. 로스(Douglas T. Ross, 1929~2007)였습니다.

공학적 병목: 복잡한 3차원 기하학의 표현

CAD와 공구 경로(toolpath)를 계산하려면 점(Point), 직선(Line), 원호(Arc), 스플라인 곡선 등 무수히 많은 도형 요소가 상호작용해야 한다. 하나의 선분은 두 개의 점을 참조해야 하고, 각 점은 3차원 좌표와 공차, 가공 파라미터를 갖는다. 이것들을 기존의 병렬 배열 방식으로 관리하는 것은 소프트웨어 공학적으로 재앙에 가까웠다.

로스는 깨달았습니다. 공구 경로를 깎아 나가는 도중 새로운 형상이 생성되고, 형상들끼리 연결되며, 연산이 끝나면 사라집니다. 고정된 크기의 거대한 전역 배열 몇 개로는 이 유기적이고 동적인 기하학적 세계를 도저히 지탱할 수 없었습니다.

그에게는 "하나의 온전한 사물(thing)을 표현하는 독립적인 데이터 묶음"이 절실했습니다.

# 3. 혁명적 착상 — 인덱싱을 거꾸로 뒤집다 (Reverse Indexing)

1956년, 더글러스 로스는 프로그래밍 역사상 가장 위대한 발상의 전환 중 하나를 감행합니다.

하드웨어 제조사들이 만들어 둔 기존의 배열 인덱서(Array Indexer) 하드웨어를 멍하니 바라보던 로스는 머릿속에서 인자의 역할을 180도 뒤집었습니다.

평문 
[ 기존 하드웨어 인덱싱 ]
고정된 베이스 (배열 시작점)  +  가변 오프셋 (인덱스 i)

                      ▼ 뒤집기 (Flip)

[ 로스의 역인덱싱 (Reverse Indexing) ]
가변 베이스 (인스턴스 주소 p) +  고정 오프셋 (속성 필드 offset)

이 뒤집힘의 함의는 실로 엄청난 것이었습니다:

  1. 고정된 오프셋(Fixed Offset):
    • $X$ 좌표는 항상 시작점에서 $+0$ 워드 위치에 있다.
    • $Y$ 좌표는 항상 시작점에서 $+1$ 워드 위치에 있다.
    • 이름/플래그는 항상 시작점에서 $+2$ 워드 위치에 있다.
    • 이 상대적 거리(오프셋)는 해당 '형태'를 가진 사물이라면 우주가 끝날 때까지 불변입니다.
  2. 가변 베이스(Variable Base):
    • 메모리의 아무 곳에나 3워드짜리 공간을 잡습니다.
    • 그 공간의 첫 주소를 포인터 $P_1$이라고 부릅니다. 이것이 '첫 번째 점'입니다.
    • 또 다른 빈 공간에 3워드를 잡고 주소를 $P_2$라고 부릅니다. 이것이 '두 번째 점'입니다.
평문 
                 [ 역인덱싱 기반의 메모리 레이아웃 ]

   메모리 어딘가 (P1)                   메모리 다른 곳 (P2)
┌──────────────────────┐             ┌──────────────────────┐
│ +0 : x-coord (10.0)  │             │ +0 : x-coord (50.5)  │
├──────────────────────┤             ├──────────────────────┤
│ +1 : y-coord (20.0)  │             │ +1 : y-coord (80.2)  │
├──────────────────────┤             ├──────────────────────┤
│ +2 : name/flag ("A") │             │ +2 : name/flag ("B") │
└──────────────────────┘             └──────────────────────┘
   ▲ 오프셋은 고정                      ▲ 오프셋은 동일
   베이스 주소 P1                       베이스 주소 P2

로스는 이 기법에 "역인덱싱(Reverse Indexing)"이라는 이름을 붙였습니다.

그리고 서로 연관된 이종 데이터들이 오프셋 규칙에 따라 한 덩어리로 끈끈하게 결합된 이 메모리 덩어리를 라틴어 단어에서 따와 플렉스(Plex)라고 명명했습니다.

왜 이름이 'Plex'인가?

로스는 해부학이나 식물학에서 신경이나 혈관, 조직이 복잡하게 얽혀 만나는 결절점을 뜻하는 라틴어 플렉서스(Plexus, 신경총/얼기설기 얽힌 망)에서 단어를 축약해 Plex라 불렀다. 태양신경총(solar plexus)처럼, 여러 데이터 요소와 링크들이 하나의 결절점으로 모여 결합하는 형상을 본뜬 것이다.

# 4. 인스턴스화(Instantiation)와 '타입' 개념의 새벽

로스의 Plex 발명이 역사적으로 지니는 진정한 충격은 "인스턴스화(Instantiation)"라는 추상화 개념을 프로그래밍 언어 역사상 최초로 구체화했다는 점에 있습니다.

그전까지 프로그래머들에게 '데이터'란 메모리에 원래부터 박혀 있는 고정된 변수나 배열이었습니다. 하지만 Plex의 세계관에서는 사고의 순서가 완전히 바뀝니다:

  1. 타입의 정의(Type Specification): "한 사물은 오프셋 0번에 $X$, 오프셋 1번에 $Y$, 오프셋 2번에 이름을 가진다"는 설계도를 먼저 정의합니다.
  2. 실체화(Instantiation): 그 설계도를 바탕으로 메모리의 임의의 위치에 필요한 만큼 독립적인 실체($P_1, P_2, P_3 \dots$)를 찍어냅니다.

오늘날 객체지향 프로그래밍(OOP)이나 시스템 언어에서 new, malloc, 혹은 스택 할당을 통해 구조체를 인스턴스화하는 모든 행위의 유전적 원형이 바로 1956년의 Plex였습니다.

로스는 1961년 발표한 기념비적인 논문 "A Generalized Technique for Symbol Manipulation and Numerical Calculation"에서 이를 수학적, 공학적 언어로 엄밀하게 정립했습니다.

# 5. 그물망의 형성 — 포인터와 관계형 링크 (Relational Links)

하지만 로스의 구상은 단순한 데이터 팩(data pack)에서 멈추지 않았습니다. Plex의 진정한 위력은 Plex 안에 다른 Plex를 가리키는 포인터를 저장할 수 있다는 사실에서 폭발했습니다.

로스는 Plex의 구성 요소를 세 가지로 분류했습니다:

  1. 데이터 성분(Data Components): 정수, 실수 등 실제 수치 정보.
  2. 링크 성분(Linkage Components): 다른 Plex를 가리키는 메모리 주소(포인터).
  3. 태그/동작 성분(Flag/Subroutine Components): 타입 식별자 및 실행할 서브루틴의 주소.

예를 들어 기하학에서 하나의 선분(Line Plex)을 정의한다고 가정해 보겠습니다:

평문 
       Line Plex (L1)
┌───────────────────────────┐
│ +0 : Line ID (#101)       │
├───────────────────────────┤
│ +1 : Pointer to Start ────┼───────►  Point Plex (P1)
├───────────────────────────┤         ┌───────────────────┐
│ +2 : Pointer to End   ────┼──┐      │ +0 : X (0.0)      │
├───────────────────────────┤  │      ├───────────────────┤
│ +3 : Stroke Style (DASH)  │  │      │ +1 : Y (0.0)      │
└───────────────────────────┘  │      └───────────────────┘
                               │
                               ▼       Point Plex (P2)
                              ┌───────────────────┐
                              │ +0 : X (100.0)    │
                              ├───────────────────┤
                              │ +1 : Y (50.0)     │
                              └───────────────────┘

선분 $L_1$은 두 끝점의 좌표를 자신이 직접 복사해 들고 있지 않습니다. 오프셋 1번과 2번에 각각 $P_1$과 $P_2$의 주소를 '링크'로 담고 있을 뿐입니다. 만약 점 $P_1$의 좌표가 이동하면, $P_1$을 참조하고 있던 모든 선분과 면의 형상이 일제히 업데이트됩니다.

Plex들이 포인터를 매개로 서로를 가리키며 거대한 유향 그래프(Directed Graph)와 관계형 그물망을 형성하는 구조—로스는 이것을 "Plex들의 우주(Universe of Plexes)"라고 불렀습니다.

# 아이반 서덜랜드와 Sketchpad(1963)로의 직결

이 설계는 곧바로 컴퓨팅 역사의 또 다른 거대한 폭발로 이어졌습니다.

1963년, 같은 MIT의 아이반 서덜랜드(Ivan Sutherland)는 세계 최초의 대화형 컴퓨터 그래픽스 시스템이자 최초의 객체지향적 GUI 시스템으로 평가받는 Sketchpad를 발표합니다. 라이트펜으로 화면에 선을 긋고 도형을 조작하던 Sketchpad의 내부 메모리 구조가 정확히 무엇으로 구축되었을까요? 바로 더글러스 로스의 Plex였습니다.

서덜랜드는 자신의 박사 학위 논문에서 로스의 Plex 개념을 핵심 기초로 명시하며, 마스터-인스턴스 관계, 제약 조건(constraints), 윈도우 그래픽 계층 구조를 모두 Plex 기반의 포인터 그래프로 구현해 냈습니다.

# 6. LISP의 존 매카시와의 지적 대결

팟캐스트에서 대담자들이 흥미롭게 회고하는 역사적 일화 중 하나는, 같은 시기 MIT에서 인공지능(AI)과 기호 처리를 연구하던 존 매카시(John McCarthy)와의 상호작용입니다.

존 매카시는 1958년 그 유명한 LISP를 창안하며 데이터를 묶는 자신만의 우아한 방식을 제시했습니다. 바로 Cons Cell입니다:

평문 
[ LISP Cons Cell ]
┌─────────────┬─────────────┐
│  car (Head) │  cdr (Tail) │
└─────────────┴─────────────┘

매카시의 접근법은 지극히 미니멀했습니다. "오직 2개의 슬롯(car와 cdr)만 가진 쌍(pair)만 있으면, 이것들을 재귀적으로 줄줄이 엮어 임의의 리스트와 트리를 모두 표현할 수 있다!"

하지만 로스는 매카시의 Cons Cell을 보며 고개를 저었습니다:

  • "임의의 복잡한 3차원 기하 도형을 표현하는 데 매번 2칸짜리 cons cell 수백 개를 체인으로 엮는 것은 하드웨어적으로 심각하게 비효율적이다."
  • "Plex는 임의의 크기 $N$개의 연속된 워드를 통째로 확보하고, 각 필드를 단 한 번의 오프셋 덧셈으로 접근한다. 하드웨어 메모리 레이아웃에 직접 매핑되는 내 Plex가 훨씬 강력하고 일반화된 모델이다!"

실제로 로스는 매카시에게 자신의 Plex 이론이 LISP의 리스트 구조를 특수한 부분집합으로 포섭할 수 있다고 주장했습니다. 두 천재의 이 논쟁은 이후 프로그래밍 언어 진영이 걷게 될 두 가지 거대한 갈래를 예견한 것이었습니다:

  • 수학적·기호적 추상화 (Symbolic Abstraction): LISP, 함수형 언어, 동적 연결 리스트.
  • 하드웨어 친화적 물리적 레이아웃 (Mechanical Layout): Plex, ALGOL W, C, Rust의 고정 오프셋 구조체.

# 7. 현대 프로그래밍 언어의 지형도 — Plex의 직계와 방계

오늘날 우리가 사용하는 언어들을 Plex의 관점에서 분류해 보면 매우 흥미로운 대조가 드러납니다.

언어 진영 대표 언어 데이터 레이아웃 구현 방식 Plex 철학과의 관계
정적 컴파일 진영 C, C++, Rust, Go, Zig 컴파일 타임에 모든 필드의 고정 오프셋 계산, 무비용 추상화 Plex의 순수한 직계 후손
동적 인터프리터 진영 JavaScript, Python, Ruby 런타임 해시 테이블(딕셔너리) 기반 문자열 키 룩업 Plex 개념의 해체 및 우회
현대 JIT 최적화 엔진 V8 (JS), PyPy, HotSpot Hidden Class / Shape / Map을 런타임에 합성하여 오프셋 캐싱 런타임에 필사적으로 Plex를 재발명

# C와 Rust: 하드웨어 기계와의 완벽한 일치

C 언어의 p->y나 Rust의 p.y는 실행 시점에 아무런 이름 검색도 하지 않습니다. 컴파일러는 이미 y가 베이스 포인터로부터 정확히 $+4$ 바이트 혹은 $+8$ 바이트 떨어진 곳에 있다는 사실을 알고 있습니다. 기계어로 번역되면 단 한 줄의 어셈블리 명령어가 될 뿐입니다:

nasm 
mov eax, [rdi + 4]   ; rdi(베이스 포인터)에 고정 오프셋 4를 더해 즉시 읽기

하드웨어 CPU의 L1 캐시 라인과 주소 연산 유닛(AGU)은 이 구조에 완벽하게 최적화되어 동작합니다. $O(1)$의 완벽한 결정론적 성능입니다.

# JavaScript와 동적 언어의 아이러니

반면 초기 JavaScript나 Python 같은 동적 언어는 객체를 단순한 "거대한 키-값 해시 테이블"로 취급했습니다. obj.x를 접근할 때마다 문자열 "x"를 해시 함수에 넣고 버킷을 뒤지는 방식은 극심한 성능 저하를 불러왔습니다.

결국 구글의 V8 엔진 개발자들은 2008년 이후 무엇을 도입했을까요? 바로 히든 클래스(Hidden Class / Shape)입니다.

V8은 런타임에 객체의 프로퍼티 추가 순서를 추적하여 내부적으로 "이 객체는 Offset 0에 x, Offset 1에 y를 갖는 타입이다"라는 메타데이터를 몰래 만들고, 그 뒤부터는 C 구조체처럼 고정 오프셋으로 직접 메모리를 읽어내는 인라인 캐시(Inline Cache)를 구축했습니다.

즉, 동적 언어 생태계가 지난 20년간 수천 명의 천재 엔지니어를 갈아 넣어 도달한 성능 최적화의 종착역 역시, 1956년 더글러스 로스가 고안했던 바로 그 Plex 구조를 런타임에 흉내 내는 것이었습니다.

# 8. 결론 — 거인들의 어깨 위에서 코드를 짠다는 것

오늘날 우리는 프로그래밍을 배울 때 구조체나 클래스라는 도구를 너무나 자연스러운 공기처럼 받아들입니다.

rust 
struct Transform {
    position: Vec3,
    rotation: Quat,
    scale: Vec3,
}

에디터에서 몇 줄의 코드를 타이핑하고 빌드 버튼을 누르는 순간, 우리는 70년 전 지구상에 존재하지 않았던 세 가지 지적 도구를 동시에 사용하고 있는 것입니다:

  1. 역인덱싱(Reverse Indexing): 고정된 베이스와 가변 인덱스를 뒤집어, 가변 주소와 고정 오프셋으로 메모리를 다루는 발상.
  2. 이종 데이터 번들링(Plex): 서로 다른 크기와 의미를 가진 데이터를 하나의 원자적 실체로 취급하는 추상화.
  3. 관계형 포인터 그래프(Linkage): 실체와 실체를 연결하여 복잡한 물리 세계를 모델링하는 그물망.

더글러스 T. 로스가 MIT의 진공관 컴퓨터 옆에서 CNC 밀링 머신의 궤적을 고민하며 하드웨어 인덱서를 거꾸로 뒤집지 않았더라면, 우리가 아는 C 언어의 struct도, 객체지향 프로그래밍의 인스턴스도, 현대의 3D 그래픽스와 게임 엔진도 지금과는 전혀 다른 기괴하고 비효율적인 모습으로 출발했을지 모릅니다.

화면 위의 점(.) 하나, 화살표(->) 하나를 누를 때마다 기억할 가치가 있습니다. 그 작은 연산자 속에는, 1차원 배열이라는 거대한 지적 감옥을 탈출하기 위해 하드웨어를 뒤집어 보았던 한 선구자의 번뜩이는 통찰이 여전히 숨 쉬고 있습니다.
