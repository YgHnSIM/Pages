# 점(.) 연산자의 디스크립터 메커니즘과 Bound Method 동적 생성

my_dog.bark와 같이 인스턴스를 통해 메서드에 접근하는 순간, 파이썬 인터프리터는 원본 함수 객체의 __get__ 디스크립터 프로토콜을 발동하여 함수 객체와 인스턴스 객체를 결합한 임시 래퍼 객체인 <bound method>를 힙 메모리에 즉석 생성함을 발견했다. 이는 정적 바인딩이 아니라 런타임 동적 객체 생성(m1 is m2 -> False, m1 == m2 -> True)이며, 메서드 호출 ()은 이 래퍼 객체를 통해 self를 첫 번째 인자로 전달하는 2단계 절차임을 규명했다.

## Evidence
- my_dog.bark를 별도 변수에 두 번 할당했을 때 메모리 주소가 다른 독립 객체(is False)로 생성된다는 사실을 확인하고 깊은 통찰을 형성함.

## Implications
- 파이썬 메서드 호출이 단순 함수 점프가 아니라 런타임 객체 생성 및 인자 주입 과정임을 이해함으로써, 함수 전달, 콜백, 데코레이터, 디스크립터의 원리를 흔들림 없이 수용할 준비가 완료됨.
