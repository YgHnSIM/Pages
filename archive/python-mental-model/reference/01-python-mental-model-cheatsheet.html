파이썬 객체 & 메모리 모델 레퍼런스

이름표 바인딩, C 구조체 레이아웃, 디스크립터 및 객체 그래프 요약

1. 파이썬 객체 3대 요소와 CPython 매핑

파이썬의 모든 데이터는 C 언어 구조체(PyObject)로 구현되어 힙(Heap) 메모리에 상주합니다.

파이썬 개념 CPython C 구조체 필드 불변 여부 설명
Identity (식별자) 메모리 주소 ((uintptr_t)p) 불변 (절대 불변) id(obj)로 확인. 객체가 소멸할 때까지 유일함.
Type (타입) PyTypeObject *ob_type 불변 (기본 불변) 연산 프로토콜(슬롯) 및 메서드 사전(tp_dict) 포인터.
Value (값) 타입별 확장 페이로드 영역 타입에 따라 결정 불변 객체는 변경 불가, 가변 객체는 내부 포인터 배열 수정.
Ref Count (수명) Py_ssize_t ob_refcnt 가변 (실시간 변동) 참조 이름표 개수. 0이 되면 즉시 메모리 해제(GC).
CPython PyObject 기본 메모리 레이아웃 (64-bit 기준)
+-------------------------------------------------------------------------+
|                  PyObject_HEAD (메타데이터 영역: 16 Bytes)               |
+-------------------------------------------------------------------------+
|  ob_refcnt (8 Bytes) : 참조 횟수 카운터 (0 도달 시 메모리 즉시 해제)      |
|  *ob_type  (8 Bytes) : 타입 명세서(PyTypeObject)를 가리키는 C 포인터    |
+-------------------------------------------------------------------------+
|                  Payload (타입별 실제 데이터 저장 영역)                  |
+-------------------------------------------------------------------------+
|  예: 정수(PyLongObject)는 ob_size(8B) + ob_digit(4B) = 총 28 Bytes      |
+-------------------------------------------------------------------------+

2. 이름표 바인딩 vs 상자 모델

오개념: 상자(Bucket) 모델

C/전통적 언어의 모델: 변수가 메모리 상자 자체이며 값이 그 안에 직접 들어감.

[ 변수 x (상자) ]
+---------------+
|      10       |
+---------------+
x = 20 -> 상자 내용물 덮어씀
진실: 이름표(Label) 모델

파이썬의 실제 모델: 힙에 독립된 객체가 먼저 뜨고 변수 이름표를 끈으로 묶음.

[ 이름표 x ] ──(끈)──▶ [ 10 (객체) ]
x = 20
[ 이름표 x ] ──(끈)──▶ [ 20 (새 객체) ]
(기존 10 객체의 refcnt 감소)

3. 가변(Mutable) vs 불변(Immutable) 동작 매트릭스

구분 해당 타입 값 변경 시 동작 객체 ID 및 메모리 주소
불변 (Immutable) int, float, str, tuple, bytes, frozenset 기존 객체 수정 불가.
새 객체 생성 후 이름표 재바인딩.		 id()가 완전히 새로운 값으로 바뀜
가변 (Mutable) list, dict, set, bytearray, 사용자 인스턴스 기존 메모리 공간에서 내부 포인터 배열 수정(In-place). id()가 변함없이 동일하게 유지됨

4. 데이터와 로직의 분리 & Bound Method

파이썬은 메모리 낭비를 막기 위해 데이터(인스턴스)와 로직(클래스 함수)을 완전히 격리합니다.

점(.) 연산자와 디스크립터 메커니즘 도식
[ 클래스 Dog ] (공구함)
  └─ __dict__: { 'bark': <function Dog.bark at 0x900> } (단 1개만 존재!)
       ▲
       │ ob_type
[ 인스턴스 my_dog ] (순수 데이터)
  └─ __dict__: { 'name': '바둑이' } (함수 코드 없음!)

==================== 점(.)을 찍는 순간 ====================
my_dog.bark 실행 시:
  Dog.__dict__['bark'].__get__(my_dog, Dog) 디스크립터 호출!
       │
       ▼
<bound method Dog.bark of <Dog object at 0x800>> (힙에 임시 래퍼 객체 즉석 생성!)
  ├─ __func__ : 0x900 (Dog.bark)
  └─ __self__ : 0x800 (my_dog)

==================== 괄호 ()를 붙여 호출 ====================
my_dog.bark() 호출 시:
  임시 래퍼가 Dog.bark(self=my_dog) 형태로 첫 번째 인자에 인스턴스를 주입!
  [함수 내부 매개변수 self] ──────────▶ [my_dog 인스턴스 본체]
핵심 레퍼런스 증명 공식

파이썬의 메서드 호출 문법은 아래 코드와 100% 동일한 실행 흐름을 갖습니다:

# 문법적 표현 (단축 표기)
my_dog.bark("월월")

# 시스템 내부 실제 실행 메커니즘
Dog.bark(my_dog, "월월")

5. 네임스페이스 탐색 순서 (LEGB 규칙)

  1. L (Local): 함수 또는 람다 내부의 지역 변수 이름표
  2. E (Enclosing): 클로저 또는 외부 중첩 함수의 이름표
  3. G (Global): 현재 모듈 최상단에 선언된 이름표
  4. B (Built-in): 파이썬 내장 네임스페이스 (len, print, range 등)
