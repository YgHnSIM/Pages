LESSON 0001 // CPYTHON MENTAL MODEL

파이썬 멘탈 모델 뇌 이식

이름표 바인딩, C 구조체(PyObject) 해부, 그리고 점(.)에 의한 Bound Method의 실시간 탄생

프롤로그: 상자를 부수고 메모리 광장으로

C나 Java 같은 전통적인 정적 컴파일 언어를 먼저 접한 개발자들은 변수를 '값을 담는 상자(Bucket)'로 상상합니다. 하지만 파이썬의 세계에서 변수는 상자가 아닙니다. 파이썬의 모든 데이터는 컴퓨터의 힙(Heap) 메모리라는 거대한 광장에 서 있는 독립된 생명체(객체)이며, 변수는 그 객체의 손목에 묶어둔 '이름표(Label)'에 불과합니다.

이 근본적인 멘탈 모델 하나만 바뀌어도, 파이썬의 가변(Mutable) 객체 참조 버그, self의 정체, 그리고 객체 지향 메서드 호출의 비밀이 모두 하나의 시스템 논리로 통합됩니다.

1부: 10000이라는 정수를 CPython 수준에서 해부하다

파이썬에는 원시 타입(Primitive Type)이 존재하지 않습니다. 숫자 10000조차 메모리 힙에 할당된 28바이트짜리 C 언어 구조체(PyLongObject)입니다.

CPython 64-bit PyLongObject(10000) 메모리 레이아웃
+-------------------------------------------------------------------------+
|                PyObject_VAR_HEAD (메타데이터 헤더: 24 Bytes)              |
+-------------------------------------------------------------------------+
|  ob_refcnt : 8 Bytes  (이 객체를 가리키는 이름표 개수 = 참조 카운트)         |
|  *ob_type  : 8 Bytes  (객체의 행동 규격서: PyLong_Type의 메모리 주소)       |
|  ob_size   : 8 Bytes  (가변 길이 정수 배열의 크기 단위)                    |
+-------------------------------------------------------------------------+
|                Payload (실제 데이터 페이로드: 4 Bytes)                   |
+-------------------------------------------------------------------------+
|  ob_digit  : 4 Bytes  (실제 정수 데이터 값: 10000)                       |
+-------------------------------------------------------------------------+
  총 메모리 점유: 28 Bytes (C 언어 int가 4 Bytes인 것에 비해 7배의 풍부한 메타데이터)
💡 C 표준 추상기계 vs 파이썬의 '객체' 차이

C 언어 표준(ISO C)에서 객체는 단순히 '값을 담을 수 있는 메모리 저장 공간(Region of data storage)'입니다. 스택에 선언된 int a; 4바이트도 C 표준에서는 객체입니다.
반면 파이썬의 객체는 '신분증(Header: RefCount + Type Pointer)을 목에 건 힙 메모리 엔티티'입니다. 파이썬 객체는 자신이 누구이고(Identity), 무슨 일을 할 수 있는지(Type)를 스스로 알고 있습니다.

2부: 데이터와 로직의 이산가족 (인스턴스는 상태만, 클래스는 공구함)

파이썬은 메모리 낭비를 극도로 혐오합니다. 만약 강아지 1만 마리를 만든다고 해서, bark()라는 함수 코드가 메모리에 1만 개 복제된다면 메모리는 순식간에 고갈될 것입니다. 따라서 파이썬은 상태(데이터)와 행동(로직)을 철저히 분리합니다.

인스턴스 (my_dog) : 순수 데이터 창고

함수 바이트코드가 전혀 없습니다. 오직 자신의 상태(이름, 나이)만 딕셔너리에 쥐고 있습니다.

my_dog = Dog('바둑이')
my_dog.__dict__
# 결과: {'name': '바둑이'}
# (bark 함수는 여기에 없음!)
클래스 (Dog) : 공용 로직 공구함

모든 인스턴스가 공유할 함수 객체들을 단 하나만 생성하여 보관합니다.

Dog.__dict__
# 결과: {
#   'bark': <function Dog.bark>,
#   'run': <function Dog.run>
# }

3부: 점(.)을 찍는 순간 벌어지는 마법 — Bound Method의 런타임 탄생

인스턴스에 함수가 없다면, 우리는 어떻게 my_dog.bark()를 실행할 수 있을까요?
비밀은 점(.) 연산자에 있습니다.

파이썬에서 my_dog.bark처럼 점을 찍어 인스턴스를 통해 클래스 함수에 접근하는 바로 그 순간, 파이썬 인터프리터의 디스크립터 프로토콜(Descriptor Protocol: __get__)이 발동합니다. 그리고 힙 메모리에 <bound method>라는 새로운 임시 래퍼 객체를 즉석에서 찍어냅니다!

점(.)을 찍었을 때 힙에서 즉석 탄생하는 임시 래퍼 객체
m = my_dog.bark  # 점(.)을 찍는 순간!

[ 힙 메모리에 새로 생성된 Bound Method 래퍼 객체 ]
+-------------------------------------------------------+
|  Type     : <class 'method'>                          |
|  __func__ : 0x80a190 (Dog 클래스의 bark 원본 함수 포인터)   |
|  __self__ : 0x80b200 (my_dog 인스턴스 자신의 메모리 포인터)  |
+-------------------------------------------------------+
⚠️ 실제로 새 객체가 만들어진다는 결정적 증거

메서드를 두 번 꺼내어 동일 객체(is)인지 비교해보면 명확해집니다: 

m1 = my_dog.bark
m2 = my_dog.bark

print(m1 is m2)  # False! (서로 다른 힙 주소에 새로 생성된 독립 래퍼 객체)
print(m1 == m2)  # True!  (안에 쥐고 있는 함수와 인스턴스가 같으므로 동등함)

이 래퍼 객체는 "자동 실행되는 함수"가 아니라, "나중에 괄호 ()를 붙여 부르면, 내가 쥐고 있는 __self__를 첫 번째 인자로 밀어 넣어서 __func__를 실행해주마" 하고 대기하는 예약 포장지입니다.

4부: self 매개변수 화살표의 올바른 종착점

가장 많은 개발자들이 혼란을 겪는 지점입니다.

"인스턴스 입장에서 self는 클래스에 정의된 함수를 가리키는 화살표인가요?"

정반대입니다!
self는 함수를 가리키는 것이 아니라, "함수가 실행될 때, 방금 그 함수를 부른 대상 인스턴스 본체"를 가리키는 매개변수 이름표입니다.

실행 스택 프레임에서 self의 진짜 화살표 방향
[ my_dog.bark() 실행 시 스택 프레임 ]
  매개변수 self ────────(참조 포인터)────────▶ [ 힙의 my_dog 인스턴스 본체 ]
                                                     │
                                                     │ (ob_type 포인터)
                                                     ▼
                                            [ 힙의 Dog 클래스 객체 ]
                                                     │
                                                     └─ bark(<function>)

따라서 my_dog.bark("멍멍")은 내부적으로 아래 코드와 100% 동일한 기계적 변환을 거칩니다: 

# 개발자가 작성하는 표현식
my_dog.bark("멍멍")

# CPython이 실제로 실행하는 형태 (self 자리에 my_dog를 밀어 넣음)
Dog.bark(my_dog, "멍멍")
